## 一、启动与生命周期管理

### 1.1 启动方式
- **嵌入模式**: PI 无独立进程，作为 GreenHorn Express 路由的一部分随后端服务启动
- **独立 Agent 模式（可选）**: 连接独立 PI Agent 进程 `http://127.0.0.1:1001`，通过 HTTP API 通信
- **无需进程管理**: PI 代码完全嵌入在 `packages/backend/src/` 中

### 1.2 状态检测
- **嵌入模式**: 始终 running（随后端服务生命周期）
- **独立 Agent 健康检查**: GET `http://127.0.0.1:1001/api/health`（3秒超时）
- **安装检测**: 检查 `ai-agent/pi/data/config/engine.json` 是否存在
- **配置检测**: 读取 `auth.json` + `models.json` 判断配置完整性

### 1.3 停止方式
- 嵌入模式：随后端服务停止而停止
- 独立 Agent：HTTP POST 到 Agent 服务关闭

### 1.4 进程管理
- 嵌入模式无需进程管理
- 独立 Agent 模式需检测进程，但不负责启动/停止（由用户手动或 start.bat 管理）

## 二、对话接入方式

### 2.1 接口类型
- **通道 A（独立 Agent）**: HTTP API（SSE 流式），URL: `http://127.0.0.1:1001/api/chat`
- **通道 B（直接 API）**: 直接 OpenAI 兼容 API，调用 `{baseUrl}/chat/completions`
- **两种通道互不依赖**: 任一条通道可用即可工作

### 2.2 请求格式（通道 B 直接 API）
```json
{
  "messages": [
    {"role": "system", "content": "You are..."},
    {"role": "user", "content": "Hello"}
  ],
  "temperature": 0.7,
  "max_tokens": 4096,
  "stream": true
}
```

### 2.3 响应格式（SSE 流）
```
data: {"id":"...","choices":[{"delta":{"content":"Hello"},"finish_reason":null}]}
data: {"id":"...","choices":[{"delta":{},"finish_reason":"stop"}]}
data: [DONE]
```

### 2.4 流式支持
- ✅ 完整支持流式（`stream: true` 默认开启）
- 通过 `response.body.getReader()` + SSE `data:` 行解析实现

### 2.5 现有 Adapter 复用分析
- **已完成**: PIAdapter 已完整实现（状态检测 + 对话路由 + SSE 解析）
- **已实现**: PI 是当前已对接的基准引擎
- **Adapter 类名**: `PIAdapter extends EngineAdapter`（已在 `packages/backend/src/adapters/pi-adapter.ts` 中实现）
- **无需新建**: 所有功能已就绪

## 三、会话存储接入

### 3.1 引擎原生存储格式
- **格式**: JSONL（每行一个 JSON 对象）
- **文件命名**: `{timestamp}_{sessionId}.jsonl`
- **按 cwd 分目录**: `sessions/--d--program--GreenHorn--/`
- **事件类型**: session, message, session_info 三种

### 3.2 对接策略
- **已实现**: 完整读写原生 JSONL 格式
- **会话 API**: `/api/sessions` 提供列表/加载/删除/改名
- **历史恢复**: 刷新页面后自动从 JSONL 恢复会话
- **兼容旧格式**: 自动迁移旧 `.json` 格式会话

### 3.3 与会话 API 兼容
- 已完全对齐：前端通过 `/api/sessions` 获取会话列表，后端从 JSONL 读取
- 会话标题/改名通过 `session_info` 事件写入

## 四、配置接入

### 4.1 配置文件位置
- **引擎注册配置**: `ai-agent/pi/data/config/engine.json` (JSON)
- **API 认证**: `~/.pi/agent/auth.json` (JSON)
- **模型配置**: `~/.pi/agent/models.json` (JSON)
- **用户设置**: `~/.pi/agent/settings.json` (JSON)
- **环境变量**: `PI_CODING_AGENT_DIR` 控制数据目录

### 4.2 已暴露给用户的配置项
- ✅ 多供应商切换（deepseek/ollama/tongyi/zhipu/doubao/moonshot/openai）
- ✅ 模型选择（defaultProvider + defaultModel）
- ✅ Persona（按引擎隔离的人设）
- ✅ 思考级别（off/low/medium/high）
- ✅ 技能管理（触发词 + Prompt 注入）

### 4.3 读写方式
- 通过 `/api/config` 路由直接读写 JSON 文件
- 自动检测并迁移旧配置格式

## 五、工具调用接入

### 5.1 工具接口
- **不支持原生工具调用**: PI 无 MCP/原生 tools 系统
- **技能系统**: 基于关键词触发的 Prompt 注入（非工具调用）
- **技能格式**: `ai-agent/pi/data/skills/*.json`，含 trigger + prompt

### 5.2 工具暴露方案
- PI 无工具通道，通过技能系统补充
- 技能按触发词自动匹配注入 system prompt
- 支持 `alwayson` 模式（始终启用）

### 5.3 MCP 跨引擎共享
- PI 无 MCP 支持，需通过 GreenHorn 后端中转
- **方案**: 后端实现 MCP 管理服务，将 MCP 工具转为技能/Prompt 注入 PI
