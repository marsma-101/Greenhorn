# GreenHorn 部署指南

> 文档版本：v0.1 (框架)
> 适用对象：终端用户（非程序员）
> 状态：📝 框架草案 · 等待 A6 优化 + 等待 M1 开发填充具体命令
> 关联 PRD 功能：F1（项目选择 + 镜像拉取）

---

## 一、文档用途说明

本指南写给**第一次使用 GreenHorn 的用户**，目标是让用户按照这 5 个步骤，不碰终端、不配环境，直接打开 GreenHorn 界面。

> **⚠️ 对前端 / UI 开发的提示**：以下每一步都对应一个 UI 界面或状态，开发时请确保这些状态在界面上有对应呈现（进度条、报错提示、完成跳转等）。

## 步骤 1：检查环境

### 用户看到

打开 GreenHorn 启动器后，系统自动检查本机是否满足运行条件。

### 需要检查的项目

| 检查项 | 必要/可选 | 说明 | 不满足时的处理 |
|--------|----------|------|--------------|
| Node.js 18+ | ⚠️ 必要 | GreenHorn 运行依赖 | 引导下载安装 |
| 操作系统 | — | Windows 10+ / macOS / Linux | 提供对应版本的安装说明 |
| 网络连接 | ⚠️ 必要 | 需要访问镜像源和 AI 模型 API | 提示检查网络 |
| Git（可选） | 可选 | 部分镜像源可能依赖 | 无 Git 也不影响 |

### UI 设计要求

- [ ] **环境检测状态页**：绿色 ✅ / 红色 ❌ / 加载中 ⟳
- [ ] **缺少依赖时**：显示清晰的"去下载"按钮（直链官网），并提供图文指引
- [ ] **检测进度**：逐项显示，不要一次性弹全部报错
- [ ] **跳过选项**：高级用户可一键跳过检测直接启动

---

## 步骤 2：下载 GreenHorn

### 方式一（推荐）：一键脚本下载

用户运行一条命令，自动下载完整 GreenHorn 到本机。

### 方式二：GitHub Release 下载

用户前往 [GitHub Releases](https://github.com/xxx/greenhorn/releases) 下载对应平台压缩包。

### 下载内容

| 组件 | 说明 |
|------|------|
| GreenHorn 后端 | Node.js 服务 + API |
| GreenHorn 前端 | 编译后的静态页面 |
| 一键启动脚本 | `greenhorn.bat`（Windows）/ `greenhorn.sh`（macOS/Linux） |

### UI 设计要求

- [ ] **下载进度页**：显示文件名、下载速度、剩余时间预估
- [ ] **下载完成**：自动跳转到启动说明页
- [ ] **下载失败**：显示错误原因 + 重试按钮 + 备用下载渠道
- [ ] **断点续传**：中断后恢复不重头下载（如工具支持）

## 步骤 3：启动 GreenHorn

### Windows 用户

```
方式一（推荐）：双击 greenhorn.bat
方式二（终端）：在 GreenHorn 目录下运行 start.bat
```

### macOS / Linux 用户

```bash
方式一（推荐）：双击 greenhorn.sh
方式二（终端）：./greenhorn.sh
```

### 启动过程显示

启动器依次执行以下操作，每一步在终端/UI 上有对应反馈：

| 阶段 | 状态文本 | 预计耗时 | 失败处理 |
|------|---------|---------|---------|
| 依赖检查 | "正在检查运行环境..." | 1-2s | 提示缺少什么，引导安装 |
| 安装依赖 | "正在安装依赖包..." | 10-30s | 提供镜像切换/重试 |
| 启动服务 | "正在启动 Web 服务..." | 3-5s | 提示端口被占用等 |
| 服务就绪 | 🎉 服务已启动！ | — | — |
| 自动打开浏览器 | — | 即时 | 提示用户手动打开链接 |

### 启动完成后用户看到的

```
🎉 GreenHorn 已启动！

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  👉 浏览器打开：http://localhost:3020
  👉 按 Ctrl+C 可停止服务
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### UI 设计要求

- [ ] **启动欢迎页**：大标题 + 品牌 logo + 启动动画
- [ ] **进度指示器**：阶段名 + 进度条 + 当前动作描述文字
- [ ] **失败状态**：醒目报错框 + 解决建议 + 社区求助入口
- [ ] **成功页**：跳转按钮（点一下打开浏览器）+ 终端链接（备选手动粘贴）

## 附：各平台差异说明

### Windows

| 项目 | 内容 |
|------|------|
| 启动脚本 | `greenhorn.bat`（PowerShell + cmd 兼容） |
| Node.js 安装 | 引导下载 Windows 版安装包（.msi） |
| 默认端口 | 3020 |
| 关闭方式 | 关闭命令行窗口 / Ctrl+C |
| 自启动 | 创建快捷方式到启动文件夹（可选） |

### macOS

| 项目 | 内容 |
|------|------|
| 启动脚本 | `greenhorn.sh` |
| Node.js 安装 | 引导下载 macOS 版安装包（.pkg）或推荐 Homebrew |
| 默认端口 | 3020 |
| 关闭方式 | Ctrl+C / 关闭终端窗口 |
| 自启动 | 添加为 Login Item（可选） |

### Linux

| 项目 | 内容 |
|------|------|
| 启动脚本 | `greenhorn.sh` |
| Node.js 安装 | 建议使用 nvm 或包管理器（apt/brew） |
| 默认端口 | 3020 |
| 关闭方式 | Ctrl+C |
| 自启动 | systemd 服务（可选） |

## 附：排错指南（FAQ 框架）

以下为用户可能遇到的常见问题，具体解决方案在 M1 完成后填充。

| 问题 | 可能原因 | 解决方向 |
|------|---------|---------|
| 启动后浏览器打开白屏 | 前端构建未完成 / 端口冲突 | 检查终端输出日志 |
| 安装时卡在依赖安装 | 网络问题 / 镜像源不可用 | 切换国内镜像 / 重试 |
| 对话没有回复 | API Key 未配置 / Key 无效 | 检查模型引导页 |
| 端口被占用 | 其他程序占用了 3020 | 自动检测空闲端口并提示 |
| Node.js 版本过低 | 系统 Node 版本 < 18 | 引导下载最新版 |
