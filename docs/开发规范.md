## 一、正向铁律（每条都是"要怎么做"）

### 0. 已验证功能保护（最高优先级，用户 2026-08-04 定死）

**已经测试验证通过的功能和代码，禁止随意修改。**

| 规则 | 说明 |
|------|------|
| **标记已验证** | 每项验收通过的功能，在代码对应处加注释：`// ✅ 已测通（YYYY-MM-DD 验收）` 或 `rem ✅ 已测通` |
| **禁止动已验证代码** | 修改需求不涉及已验证功能时，**不改动**它（即使"顺手优化"也不行） |
| **必须改动时提交申请** | 需动已验证代码 → 先写报告：①为什么要动 ②怎么动 ③动完有什么结果/影响 ④回归测试计划。PM 批准后才能动 |
| **回归验证** | 任何涉及已验证代码的改动，改完必须跑回归：原功能实测通过才算完成 |

**原因**：历史教训——安装功能、start.bat、Hermes 对话等多次"修好→改坏→再修"，反复返工浪费大量工作量。

### 1. 所有 .bat / .ps1 文件，保存后必须验证 CRLF + 非空

```bash
# 保存后立即执行（每次改 bat 必跑）
python -c "
for f in ['start.bat','scripts/start.bat','install.bat']:
    d = open(f,'rb').read()
    assert len(d) > 1000, f'{f} too small: {len(d)} bytes'
    assert d.count(b'\r\n') == d.count(b'\n') > 0, f'{f} 必须是 CRLF'
    print(f'{f}: OK ({len(d)} bytes, CRLF)')
"
```

**原因**：LF-only 的 .bat 在 Windows 双击会闪退（已发生 2 次）。

### 2. 打包/安装/运行时用到的工程已有文件，直接复制，禁止重写

```powershell
# ✅ 正确：复制工程文件
Copy-Item (Join-Path $ProjectRoot "start.bat") (Join-Path $ReleaseDir "start.bat") -Force

# ❌ 错误：重新生成/重新拼 start.bat 内容
```

**原因**：重写会导致"工程文件 CRLF、打包出来 LF"的分叉（已发生）。

### 3. 同一份内容只维护一个位置（单一事实源）

- `start.bat` 只存在于**仓库根目录**，其他位置引用它（复制），不另存副本
- 配置/常量只定义一处（如 APP_VERSION 在 shared/constants），其他引用
- 新增文件前先检查：是否已有可复用的？

### 4. 改文件前先看现状，改后必自查

```bash
git status          # 改之前：确认工作区现状
git diff <file>     # 改之后：确认改动范围，无意外变更
```

### 5. 提交前必须完成 3 项验证

```bash
pnpm build                      # ① 编译通过
python <非空验证脚本>           # ② .bat 非空 + CRLF（如有改动）
# ③ 关键功能实测（对话/状态/下载，至少跑通一条真实链路）
```

### 6. 交付报告必须写"自测了什么、怎么测的"

- 写明：执行了什么命令、看到什么输出、哪个功能实测通过
- 不允许只写"代码已审查"

## 二、复用原则（单一事实源清单）

| 场景 | 正确做法 | 禁止 |
|------|---------|------|
| 打包绿色版 | Copy-Item 工程里的 start.bat / html / README | 重新生成这些文件 |
| 版本号 | 引用 `shared/constants` 的 APP_VERSION | 在打包脚本里另写版本号 |
| 引擎配置 | 引用 EngineDefinition（constants/index.ts） | 在 Adapter 里硬编码重复配置 |
| 能力清单 | 引用 capabilities 字段 | 前端另维护一份能力表 |

## 三、常见坑清单（历史 bug 对应的正向规则）

| # | 历史问题 | 正向规则（要怎么做） |
|---|---------|---------------------|
| 1 | LF 换行闪退（2 次） | .bat 保存后必须验证 CRLF + 非空（见铁律 1） |
| 2 | html 假下载（e.preventDefault + 假动画） | 下载按钮用真实 `<a href download>`；不做假进度条 |
| 3 | express.json 中间件缺失（P0） | 新增路由前确认中间件已挂载 |
| 4 | windowsVerbatimArguments 损坏参数 | Node spawn 用默认参数处理，不手动加 verbatim 标志 |
| 5 | errorlevel 预展开失效 | 括号块内错误判断用 `if errorlevel 1` + `setlocal enabledelayedexpansion` |
| 6 | 环境变量重定向致配置丢失 | Hermes 调用保留原生 HOME/HERMES_HOME（不重定向核心变量） |
| 7 | 状态字段不匹配（s.id vs engineId） | 前后端共用类型定义（shared/），不各自定义 |
| 8 | 交付后不推 GitHub / 仓库污染 | 交付完成 = commit + push；.gitignore 先于 add 检查 |
| 9 | 改版动不该动的（把能下载改成不能） | 只改需求涉及的代码；改前 git diff 基线，改后 diff 核对 |
| 10 | CRLF 转换清空文件未验证 | 任何文件转换操作后必须验证字节数 > 0（见铁律 1） |

## 四、执行流程（每次开发）

```
① 读需求文档 → 确认改动范围
② 检查目标代码：是否"已验证"（有 ✅ 已测通 注释）？
   ├─ 是 + 需求不涉及 → 禁止改动
   ├─ 是 + 必须改动 → 先写申请报告（为什么动/怎么动/影响/回归计划），PM 批准
   └─ 否 → 正常开发
③ 改前：git status + 读相关文件现状
④ 开发：优先复用工程已有文件（单一事实源）
⑤ 改后：git diff 自查（只改了该改的）
⑥ 验证：编译 + 非空/CRLF 检查 + 关键功能实测 + 回归（涉及已验证代码时）
⑦ 标记：本次新验证通过的功能 → 加 `✅ 已测通（日期）` 注释
⑧ 提交：commit + push（交付 = 已推送）
⑨ 交付报告：写明自测命令 + 实测结果 + 是否动了已验证代码
```
