## 二、修复 2 详细排查（Hermes chat 仍失败）

### 现象

`POST /api/engines/hermes/chat` 不再 401，但返回 CLI **usage 错误**：
```
usage: hermes [-h] [--version] [-z PROMPT] [-m MODEL] ...
```
（说明 CLI 调起来了，但 `-z "prompt"` 参数传递损坏）

### 根因定位（PM 实测对比）

| 调用方式 | 结果 |
|---------|------|
| 手动直接执行 `hermes.exe -z "hi"` | ✅ 正常回复 |
| Node spawn（不带 `windowsVerbatimArguments`） | ✅ exit 0，正常回复 |
| **适配器代码（带 `windowsVerbatimArguments: true`）** | ❌ usage 错误 |

**根因**：`hermes-adapter.ts` 第 113 行 `windowsVerbatimArguments: true` 在 Windows 下导致 `-z` 参数损坏（参数被当作整体/引号丢失）。

### 修复方法

删掉该选项（或改为 `false`）：
```typescript
const child = spawn(hermesCli, args, {
  cwd: path.dirname(hermesCli),
  timeout: 300000,
  env: { ...process.env },
  shell: false,
  // windowsVerbatimArguments: true,  ← 删掉这行（Windows 下损坏参数）
});
```

**已验证**：去掉后 Node spawn 调用 Hermes CLI 完全正常。
