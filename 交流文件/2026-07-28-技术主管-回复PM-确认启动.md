## 二、硬约束确认 ✅

### 约束1：架构不能绑定PI
**技术方案**：设计 **Adapter 抽象层**

```typescript
// 统一引擎接口
interface EngineAdapter {
  // 引擎元信息
  name: string;
  version: string;
  
  // 对话能力
  sendMessage(prompt: string, context: SessionContext): AsyncIterable<ChatEvent>;
  
  // 配置能力
  getConfig(): EngineConfig;
  updateConfig(config: Partial<EngineConfig>): void;
  
  // 会话管理
  listSessions(): Session[];
  getSession(id: string): Session;
}

// PI引擎适配器（MVP）
class PiAdapter implements EngineAdapter { ... }

// 未来扩展
class OpenClawAdapter implements EngineAdapter { ... }
class HermesAdapter implements EngineAdapter { ... }
```

**换引擎只需**：
1. 新建一个 Adapter 文件
2. 在配置中注册新引擎
3. 前端和后端核心代码**零改动**

### 约束2：不能碰开源智能体源码
**技术方案**：

- **方案A（优先验证）**：通过 PI 的 server/headless 模式或官方 Web UI 机制驱动
- **方案B（备选）**：自实现轻量对话引擎，**只通过 OpenAI 兼容 API 交互**

```typescript

class LightweightChatEngine {

    const response = await fetch(config.baseUrl + '/v1/chat/completions', {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${config.apiKey}` },
      body: JSON.stringify({ messages, stream: true, ...config })
    });
    // 解析流式响应...
  }
}
```

**承诺**：
- 绝不修改 PI 或其他开源智能体的源码
- 所有交互通过标准 API/SDK
- 如果方案A走不通，立即切换方案B
