## 二、🔴 问题 1：pnpm 10 的 build scripts 被忽略 → 安装必失败

### 现象

`pnpm install` 报 `ERR_PNPM_IGNORED_BUILDS: Ignored build scripts: esbuild@0.21.5, esbuild@0.28.1`

### 根因

pnpm 10+ 的**安全策略**：默认**忽略依赖的 build scripts（postinstall）**，esbuild 需要 postinstall 下载平台二进制，被忽略后安装失败。

### 当前配置（无效）

`pnpm-workspace.yaml` 里是：
```yaml
allowBuilds:
  better-sqlite3: set this to true or false
  esbuild: set this to true or false
```
⚠️ 值 `set this to true or false` 是**占位符**，未真正配置！

### 修复方案（pnpm 10 标准写法）

`pnpm-workspace.yaml` 改为：
```yaml
packages:
  - 'packages/*'

onlyBuiltDependencies:
  - esbuild
  - better-sqlite3
```

> 或运行 `pnpm approve-builds` 交互式确认，然后把结果固化到 yaml。
> 验证：全新目录 `pnpm install` 无报错、esbuild 二进制正常生成。

## 三、🔴 问题 2：start.bat 的 errorlevel 判断失效

### 现象

用户日志显示：
```
if 0 NEQ 0 (
```
（`%errorlevel%` 被展开成 `0`，永远不成立）

### 根因

cmd 批处理经典坑：**括号块内 `%errorlevel%` 在块解析时就被预展开为旧值 0**，导致错误检测全部失效——即使 pnpm 失败了，脚本仍继续执行（"Backend built"是假的）。

### 修复方案

改用 `if errorlevel 1` 语法（运行时动态判断，不受预展开影响）：

```batch
if errorlevel 1 (
    echo [错误] ...
    pause
    exit /b 1
)
```

**涉及**：`scripts/start.bat`、`scripts/launcher.js`（如有同类逻辑）所有错误检测。
