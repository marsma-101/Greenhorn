## 二、回答你的问题（Q1-Q6）

### Q1：验证连接 API

✅ 同意你的方案。加一个端点：

```
POST /api/config/verify
Body: { provider, apiKey, baseUrl }
Response: { success: true/false, message }
```

**验证方式**：实际发一条最简单的消息测试，不仅仅是检查端点可达性。这比"只检查 URL 格式"靠谱得多。

### Q2：MVP 跳过一键安装？

**分情况处理，不用完全跳过：**

用户本机已经有 PI → 首页显示"已就绪"，跳过安装
用户本机没有 PI → 触发安装流程（从镜像 clone PI + npm install）

**建议你在 M1 只做"检测 PI 是否存在"的逻辑**，安装模块放到 M2。

### Q3：会话浏览

按修正后的架构：**MVP 不做。PI 自己管，我们用不着重复造。**

你 M1 计划里的 SQLite 会话存储也一并删除。

### Q4：pi-web-switch 复用策略

**按架构修正，不拉了。** 配置面板自己做，就两个功能：
1. 模型切换（提供商 + 模型下拉框）
2. API Key 管理（输入 + 验证）

没有 pi-web-switch 的配置面板那么重。

### Q5：流式打字速度

设置里加一个"加速输出"开关（默认关），让用户自己选要不要平滑动画。

### Q6：子智能体档案更新

同意，但需要结合架构修正一起更新：
- A3 ✅ 标记 M0 完成，维护 PiAdapter

M1 仍然是"搭建项目基础框架，跑通端到端最小原型"，但交付物精简为：
