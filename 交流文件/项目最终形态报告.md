## 第一部分：产品定义

### 一句话定位
> **开源智能体"产品化外壳"——给非程序员使用的零门槛 AI 智能体启动器。**

### 核心原则
GreenHorn **不做 PI 已经能做的事，只做 PI 做不到的事——给 PI 穿一层网页衣服。** 同样适用于未来接入的其他引擎。

### 目标用户
- 不会使用终端的普通用户
- 不知道 API、Key、命令行为何物的人
- 想要 AI 帮忙但被配置门槛劝退的人

## 第二部分：架构约束（常驻）

### 架构图

```
浏览器 ←── http://localhost:1001 ──→ GreenHorn 后端（Node.js）
                                          │
                                          │ 调 PI SDK / OpenAI 兼容 API
                                          ▼
                                      PI 引擎（或其他引擎）
```

### 不可违反的 3 条架构铁律

| # | 铁律 | 说明 |
|---|------|------|
| 1 | **不绑定 PI** | Adapter 层抽象，换引擎只写一个 Adapter 文件 |
| 2 | **不碰开源代码** | 不修改 PI、Ollama 等任何开源项目的原始代码 |
| 3 | **不做引擎已有的** | 会话管理、参数面板、数据统计等引擎自带的功能不重复造 |

### 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 后端端口 | 1001 | 不冲突、好记；Windows 无权限问题 |
| 前端 | React 18 + Vite + Tailwind CSS | |
| 后端 | Node.js + Express | 极薄 Web Server ≈ 200 行 |
| 通信 | SSE | 流式对话 |
| 对话 | 轻量引擎（方案B） | 直接调 OpenAI 兼容 API，后期可切 PI SDK |
| 通信 | SSE | 流式对话 |
| 对话 | 轻量引擎（方案B） | 直接调 OpenAI 兼容 API，后期可切 PI SDK |
| 配置 | 读写 `~/.pi/agent/auth.json` | 不建独立数据库 |
| 供应商 | 硬编码预设 7 家 | MVP 不搞配置文件覆盖 |

## 第三部分：产品规范（常驻要求）

### A. 小白零基础铁律

> **验收任何功能前，先假设用户电脑是全新的，除了操作系统什么都没有。**

#### 启动链检查清单（每个入口必审）

| # | 问题 | 标准 |
|---|------|------|
| 1 | 用户知道双击哪个文件吗？ | 文件名是人话，桌面有快捷方式 |
| 2 | 没装 Node.js 怎么办？ | **引导自动安装**，不是只报错就算了 |
| 3 | 没装 pnpm 怎么办？ | 自动降级或引导安装 |
| 4 | 端口被占用了怎么提示？ | 中文人话 + 解决方案 |
| 5 | 编译失败了呢？ | 中文错误 + 下一步做什么 |
| 6 | 成功了怎么知道？ | 明确提示"已启动，去浏览器吧" |

#### 三条铁律

1. **不自作多情假设用户有编程环境**（Node.js、npm、pnpm、Git 都不默认存在）
2. **失败必须导向动作**——只报错等于没报错
3. **验收前先用小白视角走一遍**——全新的系统/新用户从头跑一次

### B. 启动体验规范

**用户双击 .bat 后应该经历：**

```
双击
  ↓  1 秒内
cmd 窗口弹出，显示中文文字（不是乱码、不是英文）
  ↓  逐行显示进度
[1/5] 检查环境...  ✅ Node.js 已就绪
[2/5] 检查编译...   ✅ 已编译
[3/5] 启动服务...
[4/5] 检测端口...
[5/5] 打开浏览器...
  ↓
浏览器弹出 http://localhost:1001 → 看到引擎选择页面
  ↓
cmd 窗口显示 "GreenHorn 已启动 ✅"
```

**不允许出现的情况：**
- ❌ 窗口一闪就关，用户什么都看不到
- ❌ `'node' 不是内部或外部命令` 然后窗口关闭
- ❌ 报错信息是英文
- ❌ 需要用户自己打开浏览器手动输入 localhost

### C. 前端 UI 规范

| 要求 | 说明 |
|------|------|
| 当前页面 | 首页 / 对话 / 设置 / 安装引导 |
| 待实现页面 | 对话历史列表（切换/恢复会话）、文件选择器、智能体设置 |
| 设置极简第一阶段 | 只做模型切换 + Key 管理 + 主题 |
| 不做统计/仪表盘 | 用户不需要知道 token 消耗 |
| 三段式消息 | 思考过程 → 工具调用 → 最终回复，视觉上清晰区分 |
| 错误提示说人话 | 不是"401"，是"Key 好像不对哦" |

### D. 模型供应商选择规范

| 标准 | 说明 |
|------|------|
| 预设集成 | 7 家主流供应商写死在前端代码里 |
| 点选即配置 | 用户选供应商 → URL 自动填入 |
| 注册直达 | "还没有 Key？[去 XXX 官网获取]" 一键跳转 |
| Ollama 优先验证 | 先用本地模型零成本测试链路，再去申请付费 Key |

### E. 安装引导规范

用户选引擎后需要完成：

```
① 选引擎 → ② 选保存路径 → ③ 自动拉取+安装 → ④ 配模型 → ⑤ 开始对话
```

所有步骤 GUI 化，不允许用户碰命令行。

### 📅 第二阶段：功能完善（当前阶段）

**核心目标**：将 PI 原生所有用户可配置的内容，在 GreenHorn 前端都有对应的 UI。

**原则**：不自己实现 PI 已有的功能。前端调后端接口，后端从 PI 的原生文件/API 拉数据。

| 优先级 | 功能 | 说明 | PI 对接方式 |
|--------|------|------|------------|
| **P1** | 对话历史管理 | 查看历史、切换对话、恢复上下文 | 后端读取 `~/.pi/agent/sessions/*.jsonl` |
| **P1** | 对话历史 API | `GET /api/sessions` 列表、`GET /api/sessions/:id` 加载 | 解析 JSONL 返回前端 |
| **P2** | 文件选择 | 选文件发给 AI 做上下文 | 前端读取文件 → 注入对话 prompt |
| **P2** | 智能体设定 | 自定义 AI 角色/行为指令 | 自定义 system prompt |
| **P2** | 主题管理 | 自定义 TUI 颜色主题 | 读写 `themes/*.json` |
| **P2** | 提示词模板 | 管理/创建 `/模板名` 快速展开 | 读写 `prompts/*.md` |
| **P2** | 隐藏思考过程 | 开关 `hideThinkingBlock` | 读写 `settings.json` |
| **P3** | 技能管理 | 查看/安装/卸载技能 | 读写 `skills/` 目录 |
| **P3** | 扩展管理 | 查看/安装扩展 | 读写 `extensions/` 目录 |
| **P3** | 会话设置 | compaction、sessionDir、retry | 读写 `settings.json` |

**第二阶段的最终判断标准**：
```
用户在 GreenHorn 前端能完成 PI 原生的所有配置操作，
不需要打开任何 JSON 文件或命令行。
```
