## 第一部分：产品定义

### 一句话定位
> **开源智能体"产品化外壳"——给非程序员使用的零门槛 AI 智能体启动器，一个前端适配所有智能体软件。**

### 核心原则
GreenHorn **不做引擎已经能做的事，只做引擎做不到的事——给引擎穿一层网页衣服。**
同样适用于未来接入的所有引擎（PI / Hermes / Claude Code / Codex / OpenClaw / OpenCode / Reasonix）。

### 目标用户
- 不会使用终端的普通用户
- 不知道 API、Key、命令行为何物的人
- 想要 AI 帮忙但被配置门槛劝退的人

### 产品愿景（2026-08-01 用户明确）
1. **一个前端适配所有智能体软件**——选引擎、安装、对话统一体验
2. **多智能体协作**——标签栏切换 + 智能体间互相通信派任务（PI 派任务给 Hermes 等）
3. **重装系统不丢数据**——数据位置管理 + 迁移备份
4. **全新安装零门槛**——网页安装器从 GitHub/镜像拉取

## 第二部分：架构约束（常驻）

### 架构图

```
浏览器 ←── http://localhost:1001 ──→ GreenHorn 后端（Node.js）
                                          │
                                          │ Adapter 层（统一协议）
              ┌───────────┬───────────┬──────────┐
              ▼           ▼           ▼          ▼
           PI 引擎     Hermes     Claude Code   Codex ...
        （各引擎装 ai-agent/<引擎>/program/，数据在 data/）

多智能体协作：
        AgentBus（消息总线）←→ 各引擎独立会话上下文
        协作 Skill（agent-collab）实现智能体间通信
```

### 不可违反的 3 条架构铁律

| # | 铁律 | 说明 |
|---|------|------|
| 1 | **不绑定任何引擎** | Adapter 层抽象，换引擎只写一个 Adapter 文件 |
| 2 | **不碰开源代码** | 不修改任何开源项目的原始代码 |
| 3 | **不做引擎已有的** | 引擎自带的功能不重复造 |

### 数据位置架构（2026-08-01 定稿）

```
GreenHorn/
└── ai-agent/                    ← 所有引擎统一安装目录
    ├── pi/
    │   ├── program/             ← 引擎程序（源码复制/克隆）
    │   └── data/                ← 数据目录（配置/Key/模板/技能/会话）
    │       ├── sessions/
    │       ├── prompts/
    │       ├── skills/
    │       └── config/
    ├── hermes/ ...
    ├── claude-code/ ...
    └── README.md                ← 各程序位置说明
```

**铁律：数据默认不装 C 盘**（GreenHorn 在 C 盘时启动提醒；引擎统一 ai-agent/）。

### 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 后端端口 | 1001 | 固定 |
| 前端 | React 18 + Vite + Tailwind CSS | |
| 后端 | Node.js + Express | |
| 通信 | SSE | 流式对话 |
| 会话存储 | 各引擎原生格式（PI 用 jsonl） | 单一数据源，不建独立数据库 |

## 第三部分：产品规范（常驻要求）

### A. 小白零基础铁律

> **验收任何功能前，先假设用户电脑是全新的，除了操作系统什么都没有。**

启动链检查清单（每个入口必审）：用户知道双击哪个文件、没装 Node 怎么办、端口占用怎么提示、编译失败怎么说人话、成功怎么知道。

三条铁律：
1. **不自作多情假设用户有编程环境**
2. **失败必须导向动作**——只报错等于没报错
3. **验收前先用小白视角走一遍**

### B. 启动体验规范

双击 start.bat → cmd 中文进度 → 浏览器弹出引擎选择页 → "GreenHorn 已启动 ✅"。
不允许：窗口一闪就关、英文报错、手动输 localhost。

### C. 前端 UI 规范

| 要求 | 说明 |
|------|------|
| 首页 | 引擎选择页：6 张智能体卡片（图标+名称+一句话介绍+状态徽标）+ 更多引擎入口 |
| 对话页 | 左上角**当前智能体标识**（标签，多智能体运行入口预留） |
| 设置页 | 模型来源 / 外观 / 高级 / 智能体（模板+技能库）/ 数据管理 |
| 设置自动保存 | 所有设置修改立即同步后端，不设"保存"按钮 |
| 三段式消息 | 思考过程 → 工具调用 → 最终回复 |
| 错误提示说人话 | 不是"401"，是"Key 好像不对哦" |
| 不做统计 | 用户不需要知道 token 消耗 |

### D. 模型供应商选择规范

- 预设集成 7 家主流供应商
- 点选即配置、注册直达、Ollama 保留为模型来源（首页无入口，设置页可用）

### E. 引擎安装引导规范

```
① 选引擎 → ② 选位置（默认 ai-agent/）→ ③ 自动拉取（GitHub/镜像降级）→ ④ 装依赖 → ⑤ 配模型 → ⑥ 开始对话
```
所有步骤 GUI 化，不允许用户碰命令行。

## 第六部分：多智能体协作设计（B4 核心，已定稿）

### 形态（2026-08-01 用户拍板）

- **标签栏 UI**（ComfyUI 式）：每个智能体一个标签页，点击切换进入对话界面
- **点对点通信**：不限定引擎组合（PI→Hermes、OpenClaw→Claude Code 都行）
- **协作 Skill 封装**：智能体间通信固定成一个 skill（agent-collab），任何引擎装上就能参与协作

### 架构

```
[🍍 PI] [🔥 Hermes] [⚡ Codex] [➕]   ← 标签栏
        ↓ 各自独立对话界面
   AgentBus（消息总线）
    - pi / hermes / codex 各自独立会话上下文
    - send_to_agent(target, message)
    - receive_from_agent(sender, result)

agent-collab Skill 消息协议：
{ from, to, type: task|result|message, task, result, status: pending|running|done|failed }

示例：用户对 PI 说"让 Hermes 查最新10条经济新闻"
  → PI 调 send_to_agent("hermes", 任务)
  → Hermes 独立上下文执行（上网搜索）
  → 结果回传 → PI 汇总给用户
```

## 第七部分：风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 各引擎 SDK/API 差异大 | 适配工作量不确定 | B1 先做 PI+Hermes 验证，再铺开 |
| 多引擎并行内存占用 | 性能 | 先 2-3 个引擎并行，限流 |
| 远程拉取网络不稳定 | 安装失败 | 镜像降级链（已实现并实测） |
| 引擎数据目录不统一 | 迁移复杂 | 环境变量注入（PI_CODING_AGENT_DIR 等），逐个实测 |
| 小白装到 C 盘 | 重装丢数据 | 启动检测 + 提醒 + 数据迁移/备份 |
