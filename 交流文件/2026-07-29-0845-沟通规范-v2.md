## 一、核心原则

### 1. 角色分工明确

| 角色 | 做什么 | 不做什么 |
|------|--------|---------|
| **PM 小菠萝 🍍** | 写需求文档、决策、验收、统筹方向 | 🔴 **不写代码、不改项目文件** |
| **技术主管 Trae 🔧** | 读需求、写代码、实现功能、出报告 | 可以质疑需求的技术可行性 |

> PM 发现 bug 或需要改动代码时 → 写成需求文档发给 Trae → Trae 实现。
> PM 如果直接改了代码（如修 URL /v1/ 问题），属于越界行为，需要纠正。

### 2. 一个需求一个文件

**不要在一份文件里塞多个不相关的需求。** 每个独立的需求单独建文件。

| ✅ 正确 | ❌ 错误 |
|---------|---------|
| `2026-07-29-PM-安装引导界面需求.md` | 在 M1 验收文件里顺带提了安装引导的事 |
| `2026-07-28-PM-前端UX设计需求.md` | 在架构修正文件里顺带提了 UX 要求 |

### 3. 不改原文件

**任何时候都不修改已发出的文件。** 新回复、补充、修正，一律新建文件。

### 4. 定期归档

**每次里程碑关闭时，归档该阶段的所有中间对话文件。**
只保留：会议纪要、技术验证报告、设计需求文档、供应商配置等**可复用的参考文档**。

## 二、文件命名规范

```
YYYY-MM-DD-HHMM-发送人-主题.md

PM 发出： 2026-07-29-0930-PM-安装引导界面需求.md
Trae 回复：2026-07-29-1030-技术主管-回复PM-安装引导.md
PM 验收：  2026-07-29-1130-PM-验收-安装引导.md
```

**时间用 HHMM（24 小时制，4 位数），加到日期后面。** 这样按文件名排序时，同一日期的文件自然按时间排列，最新的在最上面。一眼就知道哪个文件是最后发出的。

| 发送人 | 前缀 | 后缀习惯 |
|--------|------|---------|
| PM 🍍 | `PM-` | 需求文档直接用主题；回复用 `回复Trae-主题` |
| Trae 🔧 | `技术主管-` | 回复用 `回复PM-主题`；报告用 `主题-报告` |

## 三、工作流程

```
PM 发现需求/问题
    │
    ▼
PM 写需求文档（独立文件，头部标注"待执行"）
    │
    ▼ 发给 Trae
Trae 读完后 → 归档 PM 的需求文件（移到 归档/）
    │
    ▼
Trae 评估可行性 → 确认/质疑 → 执行
    │
    ▼ Trae 完成
Trae 出交付文件（头部标注"待验收"）
    │
    ▼ PM 审查
PM 读完后 → 归档 Trae 的交付文件
    │
PM 验收通过 → **根目录只留最新的一份文件**
PM 验收不通过 → 写新的修改需求文件
```

### 每份文件的头部必须包含：

```
> 发出人：小菠萝 🍍（PM） / 技术主管（Trae）
> 接收人：技术主管（Trae） / PM 小菠萝 🍍
> 日期：2026-07-29
> 状态：待执行 / 待验收 / 已完成 / 已归档
> 引用：引用的上一份文件名（可选）
```

### 状态标签说明

| 标签 | 含义 |
|------|------|
| **待执行** | PM 发出，Trae 还未开始 |
| **执行中** | Trae 正在做 |
| **待验收** | Trae 完成，等 PM 审查 |
| **已完成** | PM 验收通过 |
| **已归档** | 已移到 `归档/` 文件夹 |

## 四、归档规则

### 什么时候归档

**每次里程碑关闭时**（M1→M2、M2→M3 等时间点）。

### 什么文件留在根目录

| 保留（参考文档） | 归档（一次性对话） |
|----------------|-----------------|
| 会议纪要 | PM→Trae 的回复文件 |
| 技术验证报告 | Trae→PM 的回复文件 |
| 设计需求文档 | 被后续文件取代的旧版本 |
| 供应商配置等可复用数据 | 进度报告 |
| 沟通规范 | 确认文件 |

### 归档后形成

```
交流文件/
├── 项目决策摘要.md             ← 全项目决策汇总（新人入口）
├── 参考文档（设计/配置/验证等）  ← 3-8 份
├── 沟通规范.md                 ← 当前沟通规则
└── 归档/
    ├── M1阶段对话记录/          ← 打包移到归档
    └── ...
```

## 五、沟通纪律清单

自审用，每次发文件前对照：

- [ ] 这份文件是不是只包含我该做的工作？（PM=文档，Trae=代码）
- [ ] 有没有改原文件？→ 应该新建文件
- [ ] 头部状态标签写了吗？
- [ ] 同一份文件里有没有塞超过一个需求？→ 应该拆开
- [ ] 这个对话结束后是否需要归档？
