## 四、CI/CD流水线设计

技术主管建议的GitHub Actions工作流：

### 4.1 主分支保护
- `main` 分支受保护，禁止直接推送
- 所有更改需通过 Pull Request
- PR 必须通过 CI 测试
- PR 必须通过技术主管审核

### 4.2 自动化工作流

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      - run: npm ci
      - run: npm run lint
      - run: npm test
      - run: npm run build

  # 自动发布（仅main分支）
  release:
    needs: test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
          registry-url: 'https://registry.npmjs.org'
      - run: npm ci
      - run: npm run build
      - run: npm publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

### 4.3 发布策略

| 分支 | 触发条件 | 发布类型 |
|------|----------|----------|
| `main` | 合并PR | 自动发布到npm（如适用） |
| `develop` | 合并PR | 自动构建，不发布 |
| `feature-*` | 提交 | 仅运行测试 |
