## 二、详细改动

### 1. `scripts/start.bat` — 完全重写

**核心变更**：不再依赖 `pnpm` 启动服务，改用 `node` 直接运行编译后的后端。

```
旧：start /min cmd /c "pnpm --filter @greenhorn/backend start"
新：start /min node "packages\backend\dist\index.js"
```

**完整流程（5步，每步都有明确反馈）：**

| 步骤 | 检查项 | 失败时提示 |
|------|--------|-----------|
| 1/5 | Node.js 是否可用 | 提示安装 Node.js |
| 2/5 | 后端是否已编译 | 自动编译（需要 pnpm） |
| 3/5 | 前端是否已编译 | 自动编译（需要 pnpm） |
| 4/5 | 启动服务（直接 `node`） | 显示启动中 |
| 5/5 | 端口检测（PowerShell Invoke-WebRequest） | 显示具体排查步骤 |

**关键改进**：
- 运行时完全不依赖 `pnpm`（`pnpm` 只用在编译阶段，且只在首次需要）
- 每步失败都有中文提示，不会一闪而过
- 端口检测用 `Invoke-WebRequest`，比 `curl` 更可靠

### 2. `scripts/launcher.js` — 修复启动器和后端启动方式

**问题**：旧版 launcher 在 production 模式下仍然打开 `http://localhost:5173`（Vite dev server 端口），但生产模式没有 Vite 服务，导致浏览器显示错误。

**修复**：
- 自动检测前端是否已构建，有构建产物时 `APP_URL = http://localhost:3000`
- 生产模式用 `node` 直接启动后端，不经过 `pnpm`
- 生产模式 HTML 页面中的 `fetch` 和 `window.open` 都使用正确的 `APP_URL`

### 3. `/settings` 404 排查结果

**已排查**：源码中没有任何地方调用 `/api/settings`，前端 `SettingsPage` 调用的是 `/api/config`。生产模式下 `pnpm build` 后测试：

```
http://localhost:3000/                → 200 ✅
http://localhost:3000/chat            → 200 ✅
http://localhost:3000/settings        → 200 ✅
http://localhost:3000/settings/advanced → 200 ✅
http://localhost:3000/api/config      → 200 ✅
http://localhost:3000/api/model-providers → 200 ✅
```

**推测**：404 可能是由 launcher 打开错误端口（5173）导致的。该问题已随 launcher 修复一并解决。
