## 一、现象

双击 `scripts/start.bat` → 完全没反应，浏览器没打开，命令行窗口一闪就关。

---

## 二、排查的3个问题

### 问题 1（严重）：`pnpm start` 实际走的是 tsx 开发模式，不是编译后的代码

`packages/backend/package.json` 第11行：

```json
"start": "tsx src/index.ts"   ← 运行 TypeScript 源码
```

这不是生产模式。生产模式应该：

```json
"start": "node dist/index.js"   ← 运行编译后的 JS
```

**但是** `dist/index.js` 有 ESM 缺失 `.js` 扩展名的问题，所以改完这行后还要修编译配置。

#### 完整修复顺序

| 步骤 | 改什么 | 说明 |
|------|--------|------|
| ① | 根 `tsconfig.json` | 给 `moduleResolution` 加 `.js` 扩展名，或后端改 `"module": "commonjs"` |
| ② | 确认 `pnpm build` 顺序 | shared → backend → frontend，依次 build |
| ③ | 改 `start` 脚本 | `"start": "node dist/index.js"` |
| ④ | 重新编译 | `pnpm build` 确认全链路编译通过 |

### 问题 2（使用体验）：bat 失败时无任何提示

`start.bat` 用 `start /min cmd /c "..."` 启动后端，但如果后端启动失败（比如 `pnpm` 找不到、`tsx` 没装），**错误信息被吞掉了**，用户看到的唯一反应就是"双击没反应"。

**需要加启动检测**比如：

```batch
:: 启动后端后检查端口是否真的在监听
timeout /t 3 /nobreak >nul
curl -s http://localhost:3000 >nul 2>&1
if %errorlevel% neq 0 (
    echo ❌ 后端启动失败，请检查：
    echo   - 是否已运行 pnpm install
    echo   - 是否所有依赖已安装
    pause
    exit /b 1
)
```

### 问题 3（环境依赖）：`pnpm` 可能不在系统 PATH 中

Desktop 双击 bat 时，cmd 继承的是系统 PATH。如果在机器上全局装了 pnpm（`npm i -g pnpm`），PATH 里有 AppData/Roaming/npm 就没问题。

但如果是通过 .workbuddy 的管理版 Node 安装的，PATH 里可能没有 pnpm。bat 运行时会报 `'pnpm' 不是内部或外部命令`，但由于问题2的静默启动，用户看不见。
