## 二、第二阶段核心目标

> **将 PI 原生所有用户可配置的内容，在 GreenHorn 前端都有对应的 UI。**
> 用户不需要打开任何 JSON 文件或命令行来完成配置。

### 架构原则（重要）

```
前端（React）         后端（Express）          PI 原生
    │                     │                    │
    │  GET /api/sessions  │                    │
    ├────────────────────→│  读 JSONL 文件       │
    │←────────────────────┤────────────────────→│
    │                     │                    │
    │  GET /api/settings  │                    │
    ├────────────────────→│  读 settings.json   │
    │←────────────────────┤────────────────────→│
    │                     │                    │
    │  PUT /api/settings  │                    │
    ├────────────────────→│  写 settings.json   │
    │←────────────────────┤────────────────────→│
```

**不要自己实现 PI 已有的功能。** 所有数据从 PI 的原生文件读取或写入。前端只管展示，后端负责和 PI 文件打交道。

## 三、任务优先级

### 第一批（P1）

#### P1-1：对话历史管理 API + 前端

**后端 API**：

| API | 说明 |
|-----|------|
| `GET /api/sessions` | 列出所有历史会话，返回 `[{id, title, time, summary}]` |
| `GET /api/sessions/:id` | 加载指定会话的完整消息列表 |
| `DELETE /api/sessions/:id` | 删除指定会话 |

**数据来源**：读取 `~/.pi/agent/sessions/*.jsonl` 文件。PI 的会话格式见其 `docs/session-format.md`。

**前端**：

```
对话页面顶部新增下拉选择器：
┌─ 当前对话 ───────────────────┐
│ 🔽 帮我写一个 API（5分钟前）    │
│  ├ 帮我写一个 API             │
│  ├ React 问题（1小时前）       │
│  ├ 项目架构讨论（昨天）        │
│  └ + 新建对话                 │
└──────────────────────────────┘
```

切换会话时：加载该会话的消息到前端消息列表。
新建对话时：创建新的空会话，不发送到 PI。
页面刷新时：恢复到最后一次打开的会话。

#### P1-2：对话历史保持

**问题**：当前刷新页面 → 消息全丢。

**修复**：
1. 前端在每次收到回复后将消息保存到当前 session 的 `messages` 状态
2. 页面加载时调 `GET /api/sessions/:lastId` 恢复
3. 不需要每次对话都写 PI 文件，前端自己维护即可
