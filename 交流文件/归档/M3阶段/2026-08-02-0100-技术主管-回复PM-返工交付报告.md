## 二、修复详情

### ✅ 修复 1：首页引擎状态匹配

**问题**：`HomePage.tsx` 用 `s.id` 匹配后端返回的 `engineId` 字段，导致所有引擎显示"未安装"。

**修复**：将 `data.engines.find((s: EngineStatus) => s.engineId === e.id)` 中的 `s.id` 改为 `s.engineId`。

**涉及文件**：`packages/frontend/src/pages/HomePage.tsx` 第 40 行。

---

### ✅ 修复 2：Hermes chat 认证

**问题**：Hermes `/api/chat` 需要认证 token，适配器直接调用返回 401。

**修复**：改用 Hermes CLI `-z` oneshot 模式：
- 命令格式：`hermes -z "<prompt>"`
- 绕过 WebSocket 认证流程
- 自动处理 system prompt 和对话历史拼接
- 支持超时（5 分钟）和错误处理

**涉及文件**：`packages/backend/src/adapters/hermes-adapter.ts`
- 新增 `buildPrompt()`：拼接 system prompt + 对话历史为完整 prompt
- 重写 `runHermesOnhot()`：使用 `-z` 参数一次性调用
- 保留 `getStatus()` HTTP 检测（该端点无需认证）

---

### ✅ 修复 3：前端接入适配层

**问题**：`ChatPage.tsx` 仍走旧 `/api/chat` 路由，实际对话由 PI 处理。

**修复**：
1. **后端 engines 路由**（`packages/backend/src/routes/engines.ts`）：
   - 将 `EngineChatResponse` 转换为前端兼容的 `ChatEvent` SSE 格式
   - `text` 类型 → `{ type: 'text', content }`
   - `thinking` 类型 → `{ type: 'thinking', content }`
   - `done` 类型 → `{ type: 'done', reason }`
   - `error` 类型 → `{ type: 'error', message }`
   - 添加 `X-Accel-Buffering: no` 头优化流式传输
   - 添加 `res.destroyed` 检查防止连接中断后继续写入

2. **前端 ChatPage**（`packages/frontend/src/pages/ChatPage.tsx`）：
   - `handleSend()` 改为调用 `POST /api/engines/${engineId}/chat`
   - 请求体使用 `EngineChatRequest` 格式：`{ messages, systemPrompt, temperature, sessionId, stream }`
   - 根据 engine 构建不同的 system prompt：
     - PI 引擎：persona + 文件上下文
     - Hermes 引擎：文件上下文（persona 通过 oneshot 传入）
   - 统一的 SSE 解析逻辑（兼容旧格式）

---

### ✅ 修复 4：引擎 persona 隔离

**问题**：所有引擎共用全局 `persona`，Hermes 不应使用 PI 的「潇潇」persona。

**修复**：
1. **后端 settings**（`packages/backend/src/routes/settings.ts`）：
   - `DEFAULT_SETTINGS` 新增 `enginePersonas: {} as Record<string, string>` 字段
   - 向后兼容：旧 `settings.json` 无此字段时自动使用默认值

2. **前端 AppContext**（`packages/frontend/src/context/AppContext.tsx`）：
   - `AppSettings` 接口新增 `enginePersonas: Record<string, string>`
   - `DEFAULT_SETTINGS` 初始化 `enginePersonas: {}`
   - 从后端加载时读取 `data.enginePersonas`
   - `updateSettings` 支持更新 `enginePersonas`

3. **前端 ChatPage**（`packages/frontend/src/pages/ChatPage.tsx`）：
   - Persona 初始化：`settings.enginePersonas[engineId]` → fallback `settings.persona`
   - Persona 同步：监听 `settings.enginePersonas`、`settings.persona`、`engineId` 变化
   - Persona 变更：保存到 `enginePersonas[engineId]` 而非全局 `persona`
   - 不同引擎独立存储各自的 persona 配置

## 六、备注

1. **Hermes oneshot 模式**：`hermes -z "prompt"` 是 Hermes CLI 的一次性对话模式，输出为纯文本，无需 WebSocket 认证。当前实现通过 CLI 子进程调用，适合本地集成场景。
2. **后续优化方向**：当 Hermes WebSocket 认证方案明确后，可切换回 WebSocket 方式以获得流式输出能力。
3. **向后兼容**：旧 `settings.json` 中无 `enginePersonas` 字段时，自动回退到全局 `persona`，确保老用户配置不受影响。
