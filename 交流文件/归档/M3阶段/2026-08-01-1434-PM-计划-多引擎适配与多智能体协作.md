## 三、阶段详设

### P1：多引擎适配层（一个前端适配所有引擎）

**核心**：完善 `EngineAdapter` 接口，让所有引擎走同一套协议。

| 引擎 | 适配方式 | 能力 |
|------|---------|------|
| PI | 已有 chat-engine，封装 adapter | 对话 + 思考 + 工具 |
| Hermes | 需研究其 SDK/API | 对话 + 脚本执行 |
| Claude Code | headless 模式 / SDK | 对话 + 工具 |
| Codex | OpenAI Responses API | 对话 + 工具 |
| OpenCode | SDK / CLI | 对话 |
| Reasonix | 已确认 npm 包 | 对话（推理） |

**关键设计**：

1. **能力分级**（不是所有引擎都支持所有功能）：
```
EngineCapabilities = {
  streaming: boolean,     // 流式输出
  thinking: boolean,      // 思考过程
  toolCalls: boolean,     // 工具调用
  fileOps: boolean,       // 文件操作
  scriptExec: boolean,    // 脚本执行
  contextLimit: number    // 上下文上限
}
```

2. **统一协议**：所有引擎通过 adapter 的 `sendMessage()` 返回统一事件流（已有 ChatEvent）

3. **降级策略**：引擎不支持某能力时，前端自动隐藏/降级（如不支持思考的引擎不显示思考区）

**验收**：前端切换任意引擎对话，体验一致（能力差异有标识）

### P2：单引擎任务执行（结构化任务协议）

**目标**：给引擎下"任务"，能拿到结构化结果，而非闲聊。

**任务格式**（adapter 统一转换）：
```
用户输入：帮我写一个排序函数
        ↓ 转为任务协议
{
  "task": "编写函数",
  "constraints": ["语言: Python", "需注释"],
  "deliverable": "代码 + 说明",
  "acceptance": "可运行、有测试"
}
```

**实现方式**：
- 前端任务模式（新 UI：任务输入框 + 验收标准字段）
- adapter 把任务协议注入 system prompt
- 结果按结构化格式返回（代码块/文件变更/结论）

**验收**：任务模式下，各引擎产出格式一致的交付物

### P3：多智能体协作（标签栏 + AgentBus + 协作 Skill）✅ 已定稿

> 2026-08-01 用户拍板形态：
> - **标签栏 UI**（ComfyUI 式）：每个智能体一个标签页，点击切换进入该智能体的对话界面
> - **点对点通信**：不限定引擎组合（PI→Hermes、OpenClaw→Claude Code 都行）
> - **协作 Skill 封装**：智能体间通信固定成一个 skill，任何引擎装上就能参与协作

**核心设计**：

```
┌────────────────────────────────────────────────┐
│ [🍍 PI] [🔥 Hermes] [⚡ Codex] [➕]  ← 标签栏    │
├────────────────────────────────────────────────┤
│  PI 对话界面：                                  │
│  用户：给 Hermes 发消息，查最新10条经济新闻       │
│  PI：好的，我让 Hermes 去查                     │
│  ── Hermes 后台执行（上网搜索）──               │
│  PI：Hermes 查完了，结果如下：...               │
└────────────────────────────────────────────────┘
```

**后端 AgentBus（智能体消息总线）**：

```
┌────────────────────────────┐
│         AgentBus           │
│  pi: [会话上下文]           │
│  hermes: [会话上下文]       │  ← 每个智能体独立上下文
│  codex: [会话上下文]        │
└────────────────────────────┘
```

**协作 Skill（agent-collab）**：智能体间通信的统一接口

```
Skill 名称：agent-collab（智能体协作）
安装位置：ai-agent/<引擎>/data/skills/agent-collab/

SKILL.md 定义：
- 用途：让本智能体能给其他智能体发消息、接收任务、返回结果
- 工具：send_to_agent(target, message) / receive_from_agent(sender, result)

消息协议（JSON）：
{
  "from": "pi",
  "to": "hermes",
  "type": "task" | "result" | "message",
  "task": "查询最新10条经济新闻",
  "result": "...",
  "status": "pending" | "running" | "done" | "failed"
}
```

**协作流程**：

```
用户对 PI 说"让 Hermes 查新闻"
  → PI 调用协作 Skill 的 send_to_agent("hermes", "查询最新10条经济新闻")
  → AgentBus 投递任务给 Hermes 的会话上下文
  → Hermes 执行（调自己的搜索工具）
  → Hermes 完成后调用 receive 回传结果
  → PI 收到结果 → 汇总回复用户

任意引擎组合：PI→Hermes、OpenClaw→Claude Code、Codex→Reasonix ...
只要双方都装有 agent-collab Skill 即可协作
```

**关键点**：

| 项 | 设计 |
|----|------|
| 标签栏 | 多智能体并行会话，点标签切换（ComfyUI 式） |
| 独立上下文 | 每个智能体一个会话上下文，互不污染 |
| 通信协议 | JSON 消息（from/to/type/task/result/status） |
| 通用性 | 不绑定引擎对，任何装 Skill 的引擎都能参与 |
| 任务状态 | pending → running → done/failed，可追踪 |
| 资源 | 先支持 2-3 个引擎并行（PI + Hermes 起步） |

**验收**：用户对 PI 说"让 Hermes 查最新10条经济新闻"，PI 自动派发，Hermes 上网搜索并返回结果，PI 汇总给用户。

### P4：验收反馈闭环

**自动验收**：

| 验收类型 | 方式 |
|---------|------|
| 规则验收 | 代码可编译/测试通过/文件存在（脚本检查） |
| AI 验收 | 指挥官或独立验收 Agent 审阅结果 |
| 人工验收 | 用户确认/打回 |

**迭代循环**：
```
执行者产出 → 验收 → 通过 ✓ 完成
                  → 不通过 → 修改意见 → 执行者修改 → 再验收（最多 N 轮）
```

**验收记录**：每次任务完整记录（任务/执行者/结果/验收意见/修改次数），可追溯
