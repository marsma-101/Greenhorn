## 一、问题确认

**是迁移逻辑的 bug。** 原因：第二轮返工前用临时脚本（`temp_migrate.js`）迁移旧会话时，cwd 硬编码为：

```javascript
cwd: 'D:\\\\program\\\\GreenHorn'  // JS 字符串字面量
```

这个字符串的值是 `D:\\program\\GreenHorn`（2 个反斜杠），再经过 `JSON.stringify` 转义后，jsonl 文件中变成了 `D:\\\\program\\\\GreenHorn`（4 个反斜杠）。

**正确做法**：应该使用 `sessions.ts` 内置的 `migrateOldSessions()` 函数，它用的是 `REAL_CWD` 变量（值为 `D:\program\GreenHorn`），`JSON.stringify` 后正确输出 `D:\\program\\GreenHorn`（2 个反斜杠）。

---

## 二、修复内容

### 1. 立即修复（已完成）

用 Node.js 脚本扫描所有 jsonl 文件，检测 cwd 不等于 `REAL_CWD` 的 session 行，修正后写回。

**修复前**：
```json
{"type":"session",...,"cwd":"D:\\\\program\\\\GreenHorn"}
```

**修复后**：
```json
{"type":"session",...,"cwd":"D:\\program\\GreenHorn"}
```

### 2. 防御性修复（已完成）

在 [sessions.ts](file:///d:/program/GreenHorn/packages/backend/src/routes/sessions.ts#L284-L321) 中新增 `fixCwdEscaping()` 函数，启动时自动扫描并修复 cwd 双重转义问题，确保即使未来再有类似问题也能自动修复。
