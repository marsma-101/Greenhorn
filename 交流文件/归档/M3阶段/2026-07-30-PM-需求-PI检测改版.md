## 一、问题回顾

当前 PI 卡片在首页加载时实时检测状态，但因为 API 路径写错，一直显示"检测中..."，用户永远得不到结果。

## 二、通用检测架构（不止 PI，适用于所有引擎）

**这个"点击时按需检测"模式不只是修 PI 的 bug，而是后续所有引擎的通用机制。** 后面接入 Hermes、OpenClaw 或其他引擎时，复用同一套逻辑。

### 通用引擎卡片交互模式

```
首页展示引擎卡片（无状态文字）
    ↓
用户点击任意引擎卡片
    ↓
调 /api/{engine}/check（或统一接口 /api/engine/{id}/check）
    ↓
┌─ 已安装 ────────────┐
│  跳转到 /chat          │
│  带上 provider={id}    │
└───────────────────────┘
    OR
┌─ 未安装 ────────────┐
│  弹窗提示：            │
│  "{name} 未在本机检测   │
│   到，是否拉取安装?"    │
│                       │
│  [ 取消 ] [ 开始安装 ]  │
└───────────────────────┘
    ↓ 用户点「开始安装」
    ↓
跳转到 /setup → 安装引导（选路径→拉取→配置）
```

### 需要统一的后端接口

```typescript
// 统一检测接口
GET /api/engine/{id}/check

// 返回
interface EngineCheckResult {
  installed: boolean;
  path?: string;
  version?: string;
}
```

当前 PI 已有 `/api/pi/`，后续引擎（Hermes → `/api/hermes/check`、OpenClaw → `/api/openclaw/check`）都遵循同一模式。

### 现状
```
HomePage 加载
    ↓
立即调 /api/pi/check（但路径错了）
    ↓
卡在"检测中..." 永不更新
```

### 改后
```
HomePage 展示 4 张卡片（无状态文本）
    ↓
用户点击「📦 PI · 编码智能体」
    ↓
调 /api/pi/ 检测 PI 是否已安装
    ↓
┌─ 已安装 ────────────┐
│  跳转到 /chat        │
│  默认 provider='pi'  │
└─────────────────────┘
    OR
┌─ 未安装 ────────────┐
│  弹窗提示：          │
│  "PI 未在本机检测到   │
│   是否拉取安装?"      │
│                     │
│  [ 取消 ] [ 开始安装 ] │
└─────────────────────┘
    ↓ 用户点「开始安装」
    ↓
跳转到 /setup → 安装引导
```

### 具体改动

| 文件 | 改动 |
|------|------|
| HomePage.tsx | 去掉 `piStatus` 状态和 `useEffect` 自动检测；PI 卡片的 `onClick` 改为：先调 `/api/pi/` 检测，根据结果跳转或弹窗 |
| HomePage.tsx | PI 卡片不再显示"检测中"/"已就绪"/"未安装"等状态文字 |
| 如果需要 | 新增一个确认弹窗组件（或复用"怎么用"弹窗的样式） |

---

## 三、优点

1. **首页加载更快**——省掉一个 API 请求
2. **无歧义状态**——不再有"检测中..."这种卡住的状态
3. **用户意图明确**——主动点击才触发检测，结果即时反馈
4. **安装引导链路通**——未安装直接引导到 `/setup`
