## 一、会议背景

用户作为非程序员、不懂命令行与编程思维的**普通终端使用者**，长期同时使用两类 AI 工具：

- **闭源产品**：Trae、QClaw、WorkBuddy、Dumate 等——赢在"双击即用"，但部分功能（配置项、模型调用、VPN/Key 问题）对小白解释不清、不友好。
- **开源智能体**：PI、openclaw、Hermes 等——能力不差，但卡在**部署门槛**：要自己下前后端、看仓库说明、配环境、敲命令启动，对非程序员极不友好，尤其大量 CLI 模式项目。

用户的真实诉求：**用开源项目当引擎，做一层"开箱即用的网页/桌面外壳"，把上面所有门槛藏起来**——小白打开网页，选项目、按引导填好模型 Key、用默认值，直接对话干活。本质是**开源智能体的"产品化外壳 / 发行版"**。

## 二、想法演进（讨论过程）

1. **初始设想**：做一个前端，能对接任意一个开源智能体项目（openclaw / pi / Hermes 等）。
2. **可行性讨论（PM）**："对接任意"不能为零配置，本质是"统一前端 + 适配器层"，新增项目=加适配器。
3. **用户澄清真实意图**：自己不是程序员，代码/指令/编程思维了解不清晰。痛点来自"闭源产品对小白不友好 + 开源项目部署门槛高"。想要的是"一套前端匹配不同项目，或直接封装成桌面/网页工具，打开就是网页就能用"。
4. **PM 重新定性**：这不是"技术对接任意开源智能体"，而是**给普通终端用户做开箱即用的产品化外壳**；难点从"对接 N 个项目"转为"打包分发 + 默认配置 + 引导填 Key"。
5. **范围收敛（用户拍板）**：
   - 先做**单一引擎 PI**（路线 1），后期再接其他开源项目（预留接口）；
   - 形态先做**网页（本地网站）**，桌面应用后续再说；
   - 三大友好设计：**镜像自动拉取 / 模型 API 引导教程 / 问号 tooltip 帮助**；
   - 关键配置给**默认值 + 说明**；
   - 用户本机已有 PI 完整可运行工程 + 一个"仅展示数据、对话仍需 CLI"的 web 前端（不满足需求）。
6. **角色分工（用户明确指派）**：**小菠萝任 PM / 主导发起人**，负责定计划、节点、详细 workflow、审计标准；**用户任产品 Owner + 找专业前端与 UI 开发者**做具体编码。用户认可"AI 编程不强，但规划/生成/指导/审计没问题"。

## 三、已确认的产品决策

| 决策 | 内容 |
|------|------|
| 引擎路线 | 先做单一引擎 **PI**，后期接其他开源项目（架构预留 Adapter 层） |
| 产品形态 | **本地网页**优先，桌面应用后续 |

| 模型 API 引导教程 | 选完项目后分步引导+教程（点哪、从哪调 API、URL 填哪、Key 从哪生成），按模型分套；**MVP 先 DeepSeek**，后续补智谱/通义/豆包 |
| 问号 tooltip 帮助 | 每个按钮/功能旁小圆圈(?)，悬停弹介绍框；设置里可开/关"说明"，关掉则圆圈消失 |
| 默认值 + 说明 | 上下文长度、温度等给初始默认值并附大白话说明 |
| 本地零 Key 备选 | PI 默认走本地 Ollama（qwen3.5:9b），不想申请 Key 的用户可直接用 |

## 四、PI 工程侦察结论（PM 已执行，供开发者参考）

PI 工程位于 `D:\program\pi-agent`，结构如下：

- `source/` — PI 完整 monorepo 工程（GitHub: earendil-works/pi），含 `pi-ai`（统一 LLM API，30+ 提供商）、`pi-agent-core`（Agent 运行时，含**传输抽象**）、`pi-coding-agent`（CLI 应用 `pi` 命令）、`pi-web-ui`（官方 Web UI）、`pi-tui` 等。
- `pi-web-switch/` — 用户已有的 web 前端，是**只读管理面板**：直接读取 `~/.pi/agent/` 真实配置（`auth.json` / `models.json` / `settings.json`），能做 API Key 管理、模型/Provider 管理、设置管理、会话浏览、记忆查看。**结论：配置 UI 可复用为基座，但它只"读"不"驱动对话"**。
- `工程文件/` — PI 真实配置副本（auth.json 当前为空=本地 Ollama 无需认证；models.json 用 OpenAI 兼容 API）。

**关键结论（影响架构）：**
1. PI 走 **OpenAI 兼容 API**，**DeepSeek 是内置提供商**（DeepSeek V3 / R1）→ "先引导 DeepSeek"顺路，教程可直接套用。
2. PI 上游含官方 `pi-web-ui` 与带"传输抽象"的运行时 → **PI 具备被网页驱动的基础，不是纯 CLI 死路**。
3. ⚠️ **最关键待验证项**：网页如何真正"驱动 PI 对话"（机制可能是 server/headless 模式 / 进程管道 / 复用 pi-web-ui），必须在 M0 阶段先读 `pi-coding-agent` 与 `pi-web-ui` 源码定下来。

## 八、附录：用户原话要点（决策依据）

- "我不是程序员出身，对代码和指令类似这些编程相关的内容了解并不是很清晰……主要想利用已经存在的项目，结合终端使用的问题，帮他们解决。"
- "闭源项目大部分做成桌面应用……开源项目很多也要看仓库说明、下前后端、做配置做启动，等于还是得有编程能力，对小白不友好。"
- "我想能不能用一套前端，匹配不同的项目，或者把这些项目直接做成一个桌面应用或网页形式的工具……它就是一个网页，或者本地网站。"
- "我更倾向于网页……你选完了之后显示一个网页图标或程序安装图标……咱直接因为这个是在国内，国外的网站会被墙，所以直接从镜像拉取这个项目，拉取到他电脑里都不用他去找地址下载。"
- "模型调取这方面确实是个比较大的问题……新手和小白会在模型调用这个 VPN 上出一些问题，不会调取 API。所以咱得在网页里给引导……从哪个网站调用 API，给他说明……在哪生成 API key……这些得需要有教程。"
- "加一个小的圆圈里边有个问号，鼠标放上去弹出来介绍框……在设置里边关闭，关上了那个小圆圈就没了。对于熟悉的人就可以不用看说明。"
- "你的编程不是特别强，但你的规划和项目生成、指导应用和审计的能力应该是没问题的。所以我希望你能做这个项目的主导发起人，制定计划、制定节点、写详细的工作流程，我去找其他人分批分部做具体开发。"
