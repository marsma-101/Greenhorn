## 一、架构与技术选型确认

### Q1：前端框架选择
PRD未明确前端框架。建议如下，请PM确认：
- **方案A（推荐）**：React 18 + TypeScript + Vite + Tailwind CSS
  - 理由：生态最成熟，pi-web-switch前端基于React可复用，社区资源丰富
- **方案B**：Vue 3 + TypeScript + Vite + Element Plus
  - 理由：上手门槛略低，但pi-web-switch无法直接复用

**请PM确认**：采用哪个方案？或是否有其他偏好？

### Q2：后端框架选择
- **方案A（推荐）**：Node.js + Express + TypeScript
  - 理由：与PI生态一致（PI是Node.js工程），复用pi-web-switch后端代码
- **方案B**：Node.js + Fastify + TypeScript
  - 理由：性能更好，但生态不如Express

**请PM确认**：采用哪个方案？

### Q3：前后端通信方式
对话流式传输有两种方案：
- **方案A（推荐）**：SSE（Server-Sent Events）
  - 理由：单向流式足够（服务端→客户端），实现简单，兼容性好
- **方案B**：WebSocket
  - 理由：双向通信，但本项目主要是单向流式，WebSocket过度设计

**请PM确认**：采用哪个方案？

### Q4：包管理器
- **方案A（推荐）**：pnpm
  - 理由：速度快、磁盘占用小、monorepo支持好
- **方案B**：npm
  - 理由：最通用，无需额外安装

**请PM确认**：采用哪个方案？考虑到目标用户是小白，是否需要默认用npm减少安装步骤？

## 二、M0技术验证相关

### Q5：PI源码访问权限
PRD提到M0需要读 `D:\program\pi-agent\source` 源码。请确认：
1. 该目录是否已存在且完整？
2. 技术主管是否可以直接读取和分析该目录下的代码？
3. 是否需要Owner额外授权？

### Q6：pi-web-switch复用范围
PRD提到"复用pi-web-switch基座"。请确认：
1. `D:\program\pi-agent\pi-web-switch` 的代码是否可以直接复制/引用到GreenHorn？
2. 还是作为独立依赖（npm link / monorepo子包）引入？
3. pi-web-switch当前是否可正常运行？有无已知bug？

### Q7：PI对话驱动机制
这是最关键的技术风险。PRD列出了三种候选机制。技术主管将在M0阶段逐一验证，但请PM了解以下决策分支：
- 如果(a) PI有内置server模式 → 最优方案，直接复用
- 如果(b) 只能走进程管道 → 需要自行实现解析层，工作量增大
- 如果(c) 复用pi-web-switch的server → 需要扩展，但基座已有

**请PM确认**：如果验证发现三种方案都不可行或效果很差，是否有备选方案？还是暂停等Owner决策？

## 三、功能细节确认

### Q8：镜像拉取的具体实现
PRD提到"国内镜像自动拉取"。技术主管需要确认：
1. **源码镜像**：是否有可靠的PI源码国内镜像？（如gitee镜像、清华镜像等）
   - 如果没有现成镜像，是否需要GreenHorn自己维护一个镜像同步？
2. **依赖镜像**：npm镜像（npmmirror.com）和pip镜像（pypi.tuna.tsinghua.edu.cn）是否可直接用？
3. **模型镜像**：PI默认用Ollama本地模型，模型文件从哪拉取？是否需要支持在线API模式（跳过模型下载）？
4. **拉取失败处理**：镜像不稳定时，是否允许回退到"手动下载+指定路径"模式？

### Q9：对话界面的产物展示
PRD提到PI会产出"代码/文件"。请确认：
1. 代码产物：是否在网页内嵌代码编辑器展示？（如Monaco Editor）还是仅文本展示？
2. 文件产物：是否支持下载？是否支持预览（图片/PDF等）？
3. 工具调用过程：是否实时展示？还是仅展示最终结果？

### Q10：配置面板的复用边界
pi-web-switch已有配置UI。请确认：
1. 是**直接fork** pi-web-switch代码到GreenHorn下改造？
2. 还是**提取公共组件**，两边各自维护？
3. pi-web-switch后续如果更新，GreenHorn是否需要同步？

### Q11：会话数据存储
1. 会话历史存在哪里？`~/.pi/agent/` 下PI已有会话文件？
2. GreenHorn是否需要自己维护一套会话存储？
3. 是否需要支持会话导出（JSON/Markdown）？

## 四、GitHub开源相关

### Q12：开源许可证选择
请PM确认选择哪种开源许可证：
- **MIT**：最宽松，任何人可自由使用/修改/商用，仅需保留版权声明
- **Apache 2.0**：类似MIT，额外有专利授权保护
- **GPL 3.0**：强制衍生作品也开源，保护开源精神但限制商用

**技术主管建议**：MIT（最利于推广和新手参考）

### Q13：GitHub仓库信息
