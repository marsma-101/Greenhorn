## 一、🔴 最优先：会话与 PI 原生文件实时同步（关键！）

### 问题

当前会话只存在 `~/.pi/agent/sessions-greenhorn/`（GreenHorn 独立简化格式），**完全没有写入 PI 原生会话文件**（`~/.pi/agent/sessions/*.jsonl`）。

这导致：
1. 用户用 GreenHorn 对话的内容，PI 原生完全看不到
2. 用户后续要做"对话整理、经验汇总"等功能时无数据可用
3. 两边内容不一致，是严重缺陷

### 要求

**每次对话消息必须双写：**

```
用户发消息
  ↓
① 写入 GreenHorn 简化文件（sessions-greenhorn/xxx.json）— 前端展示用
② 同步追加写入 PI 原生 jsonl（~/.pi/agent/sessions/--路径--/时间戳_uuid.jsonl）— 数据源用
```

**PI 原生 jsonl 格式要求**（每行一个 JSON 事件）：

```jsonl
{"type":"session","id":"...","timestamp":"2026-07-31T09:00:00.000Z","cwd":"..."}
{"type":"message","id":"...","parentId":"...","role":"user","content":[{"type":"text","text":"你好"}]}
{"type":"message","id":"...","parentId":"...","role":"assistant","content":[{"type":"text","text":"你好！"}]}
```

关键点：
- `type` 字段：session / message 等（参考 PI 官方格式）
- `content` 是**数组**，每条含 `type` 和 `text`
- 写入时用 append-only（追加），不重写整个文件
- GreenHorn 读取会话时仍用简化文件（快），但写的时候两边都写

**验收标准**：
1. 用 GreenHorn 发一条消息
2. 检查 `~/.pi/agent/sessions/` 下出现对应的 jsonl 文件
3. 文件内容包含刚发的消息
4. 连续对话多条，jsonl 逐条追加
