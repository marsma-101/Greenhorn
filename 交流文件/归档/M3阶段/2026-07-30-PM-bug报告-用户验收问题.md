## 用户测试发现的问题

### P0-1：PI 卡片一直显示"检测中..."

**现象**：首页 PI 卡片显示"检测中..."，刷新也不变，永远不会变成"已就绪"或"未安装"。

**根因**：前端 HomePage.tsx:26 调用 `fetch('/api/pi/check')`，但后端只注册了 `/api/pi/` 路由（`piCheckRouter.get('/')`），没有 `/api/pi/check`。该请求不匹配任何 API 路由，落到 `app.get('*')` SPA fallback 返回 HTML，前端解析失败，`piStatus` 永远停在 `'checking'`。

**修复**：二选一
- 方案 A：前端把 `'/api/pi/check'` 改为 `'/api/pi/'`
- 方案 B：后端 piCheckRouter 增加 `get('/check')` 路由（同逻辑），同时前端不改

**推荐方案 A**，改动最小。

### P1：点击 PI 和点击 Ollama 结果一样

**现象**：用户点击首页任意引擎卡片，都进入同一个对话页面，唯一的区别是顶部标题栏的文字（"PI · 编码智能体" vs "Ollama · 本地模型"），其他一模一样。用户无法直观感受到切换了引擎。

**前端代码确认**：
- PI 卡片 → `navigate('/chat')` → 默认 provider='pi'
- Ollama 卡片 → `navigate('/chat?provider=ollama')` → provider='ollama'
- ChatPage 顶部仅显示不同文字，其余界面完全相同

**建议修复**：
1. 至少让两个进入方式有显眼的视觉区别（不同的欢迎语、不同的默认问题示例）
2. 或者按引擎显示不同的引导文案（PI 偏编码，Ollama 偏通用对话）
