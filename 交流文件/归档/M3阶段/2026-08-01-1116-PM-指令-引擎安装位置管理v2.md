## 需求背景

1. 智能体引擎（PI / Hermes / Claude Code 等）不希望装到 C 盘（C 盘空间紧张、重装系统丢数据）
2. 用户可能一开始就把 GreenHorn 程序**本身**装在 C 盘——也需要检测和提醒

**核心方案**：
- 引擎统一安装到项目内新建的 **`ai-agent/` 文件夹**
- 程序启动时检测 GreenHorn 自身位置，若在 C 盘则提醒用户移动到其他盘符

## 一、引擎安装位置：项目内 ai-agent 文件夹

### 目录结构

```
GreenHorn/                     ← 用户下载解压的 GreenHorn 程序文件夹
├── ai-agent/                  ← 🆕 所有智能体引擎装这里
│   ├── pi/                    ← PI 引擎
│   ├── hermes/                ← Hermes 引擎
│   ├── claude-code/           ← Claude Code
│   ├── codex/                 ← Codex
│   └── ...
├── start.bat
└── ...
```

### 引擎安装逻辑

| 项 | 要求 |
|----|------|
| 统一位置 | 所有引擎默认装到 `<GreenHorn目录>/ai-agent/<引擎名>/` |
| 配置跟随 | 各引擎的配置/会话/数据也放 `ai-agent/<引擎名>/data/` 下，不用 `~/.pi/agent` |
| 说明文件 | `ai-agent/README.md`：写明每个程序的位置、用途、如何更新 |
| 路径注入 | GreenHorn 启动引擎时**总是注入环境变量**（如 `PI_CODING_AGENT_DIR`）指向数据目录，覆盖引擎内部默认路径 |

### 引擎数据目录规范

```
ai-agent/<引擎名>/
├── 程序文件（引擎本体）
└── data/                 ← 数据目录（配置/Key/模板/技能/会话全在这）
    ├── settings.json
    ├── auth.json
    ├── prompts/
    ├── skills/
    ├── sessions/
    └── ...
```

**关键**：GreenHorn 启动引擎时用环境变量注入数据目录位置（`PI_CODING_AGENT_DIR` 等），
即使引擎内部写死 `~/.pi/agent`，也会被环境变量覆盖。这是"迁移后数据不丢"的根本保障。

### ai-agent/README.md 内容要求

```markdown
# AI Agent 引擎目录

本文件夹存放 GreenHorn 使用的智能体引擎程序。

| 引擎 | 位置 | 说明 |
|------|------|------|
| PI | ./pi/ | 默认对话引擎 |
| Hermes | ./hermes/ | 备用引擎 |
| ... | ... | ... |

- 安装：通过 GreenHorn 界面「引擎管理」自动安装
- 更新：在 GreenHorn 界面点击更新
- 手动查看/删除：直接操作本文件夹
```

### 用户也可自定义位置（可选）

安装引导时：
```
📁 引擎安装位置
[GreenHorn\ai-agent\        ] [浏览...]   ← 默认：项目内 ai-agent
```

- 默认 = 项目内 `ai-agent/`（零配置，推荐）
- 用户可改（如装到 D:\ai使用培训\引擎\），改了之后配置跟随所选位置

## 二、选择引擎时：检测已安装引擎 + 迁移提示

### 流程（启动 start.bat → 网页 → 选引擎）

```
① 启动 GreenHorn，进入首页
② 用户点击选择某个智能体引擎（如 PI）
③ 检测引擎是否已安装：
   ├─ 在默认位置（ai-agent/<引擎>）→ ✅ 直接启动
   └─ 不在默认位置（在别处，如 C:\xxx\pi）→ 弹窗询问
④ 弹窗：
   检测到 PI 引擎在其他位置：C:\xxx\pi
   是否迁移到默认位置（GreenHorn\ai-agent\pi）？
   [迁移] [不迁移，就用当前位置]
⑤ 选迁移 → 走「迁移三件套」（见下）
   选不迁移 → 记住自定义位置，直接启动，不再反复询问（可"不再提醒"）
```

### 🔴 迁移三件套（防数据丢失的关键）

**只搬程序 = 必丢数据。** 必须三件一起搬：

```
① 程序本体   → 复制到 ai-agent/<引擎>/
② 数据目录   → 配置/Key/模板/技能/会话 → 复制到 ai-agent/<引擎>/data/
③ 路径注入   → GreenHorn 启动时设置环境变量 PI_CODING_AGENT_DIR 指向新数据位置
```

**为什么这样不丢数据**：
- 引擎内部可能写死找 `~/.pi/agent`（C 盘用户目录）
- GreenHorn 启动引擎时**总是注入环境变量覆盖它**，指向 `ai-agent/<引擎>/data/`
- 数据跟着环境变量走 → 迁移后历史会话/Key/模板/技能全部可读
- 迁移 = 复制不删除 → 原位置保留，确认无误后可手动删

**验证迁移成功**：迁移后打开历史会话 → 检查 API Key 生效 → 检查技能可调用 → 全部通过才算成功

### 用户选"不迁移"的情况

- GreenHorn 记住该引擎的自定义位置（存配置），后续启动直接用
- 不强制，不打扰（有"不再提醒"选项）
- 数据仍在原位置，正常读取

## 三、🔴 程序自身位置检测（GreenHorn 在 C 盘时提醒）
### 需求

普通用户可能直接把 GreenHorn 程序文件夹解压/安装在 C 盘（如 `C:\Users\xxx\Downloads\GreenHorn\` 或 `C:\GreenHorn\`）。这会导致：
- 占用 C 盘空间
- 重装系统后 GreenHorn 程序 + 引擎 + 所有数据全部丢失

### 检测逻辑

启动时（start.bat 或后端启动）检查**程序所在盘符**：

| 检测结果 | 行为 |
|---------|------|
| GreenHorn 在非 C 盘（D/E/F...） | ✅ 正常，无提示 |
| GreenHorn 在 C 盘 | ⚠️ 弹出提醒 |

### 提醒界面（首次启动弹窗）

```
⚠️ GreenHorn 正在 C 盘运行

程序和数据放在 C 盘有以下风险：
1. 占用系统盘空间
2. 重装系统后程序、引擎、聊天记录会全部丢失

建议：把 GreenHorn 文件夹移动到其他盘符（如 D 盘）再运行。

[我已经知道了] [如何移动？]
```

「如何移动？」展开步骤：
```
1. 关闭 GreenHorn（关闭黑色窗口）
2. 把整个 GreenHorn 文件夹剪切到 D 盘（如 D:\GreenHorn）
3. 重新双击 D:\GreenHorn\start.bat 启动
4. 程序和数据会全部跟随，无需重新安装
```

### 检测频率

- 每次启动都检测（一次检测成本极低）
- 检测结果记住（本次运行不再重复弹窗）

## 四、数据迁移（重装系统不丢数据）

### 需要迁移的数据清单

| 数据 | 位置 | 重要性 |
|------|------|--------|
| 设置 | ai-agent/<引擎>/settings.json | 🔴 高 |
| API Key | auth.json | 🔴 高 |
| 提示词模板 | prompts/*.md | 🔴 高 |
| 技能 | skills/ | 🔴 高 |
| 聊天记录 | sessions/*.jsonl | 🔴 高 |
| 主题/扩展 | themes/ extensions/ | 🟡 中 |

### 三种触发场景

#### 场景 1：安装时检测旧数据
检测到 C 盘旧配置（如 `~/.pi/agent`）时提示迁移：
```
检测到旧版数据在 C:\Users\xxx\.pi\agent
包含：设置 / API Key / 提示词模板 / 技能 / 聊天记录
是否迁移到新位置？ [迁移] [不迁移]
```

#### 场景 2：程序内手动迁移（设置页）
```
📦 数据管理
当前数据位置：D:\GreenHorn\ai-agent\pi\
[更改位置] [备份数据] [从备份恢复]
```

#### 场景 3：重装系统后恢复
启动时检测不到数据 → 引导：
```
未检测到 GreenHorn 数据。
如果之前有备份，请选择备份位置恢复：
[选择备份位置并恢复] [全新开始]
```

### 迁移实现要求

| 项 | 要求 |
|----|------|
| 迁移方式 | 整个配置目录复制（文件复制） |
| 原子性 | 先复制到临时目录，全部成功再切换 |
| 原数据保留 | 迁移后旧位置保留，用户确认后再删 |
| 进度显示 | 进度条（SSE） |
| API Key 安全 | 界面显示打码 |
| 备份功能 | 一键打包 zip，可保存到其他盘/网盘 |
