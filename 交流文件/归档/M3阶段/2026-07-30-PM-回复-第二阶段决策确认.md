## 决策 1：会话持久化方案

**选你推荐的方案：独立简化 session 文件。**

逻辑确认：
1. 后端建独立目录 `sessions-greenhorn/*.json`，存简化格式的消息数组
2. 每次发新消息时，**双写**：写入 PI 原生 jsonl（方便用户做整理汇总）+ 写入简化文件（方便前端展示）
3. 前端选中会话时，直接从后端简化文件加载，秒开
4. 两端内容实时同步——写 PI 原生的同时也写简化文件

B 方案的"浏览器缓存 + 点击时从 PI 拉"排除，多一次网络请求，响应慢。

## 决策 2：会话名称

- **默认名称**：取第一条用户消息前 30 个字符
- **可改名**：会话列表每个条目旁加一个编辑按钮（📝），点击可修改会话名称
- 修改后存在简化 session 文件中

---

## 决策 3：settings 新字段

写入 PI 原生 `settings.json`。UI 按以下方式实现：

| 字段 | UI 控件 | 默认值 |
|------|---------|--------|
| `hideThinkingBlock` | 开关 toggle | `false` |
| `defaultThinkingLevel` | 下拉框：off / low / medium / high | `"off"` |
| `quietStartup` | 开关 toggle | `false` |
| `sessionDir` | 输入框（带默认值） | `~/.pi/agent/sessions` |
| `compaction.enabled` | 开关 toggle | `false` |
| `compaction.reserveTokens` | 数字输入 | `4096` |
