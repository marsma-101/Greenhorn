## 一、技术调研报告

### 1.1 会话存储现状

| 存储位置 | 路径 | 格式 | 状态 |
|---------|------|------|------|
| GreenHorn 简化格式 | `~/.pi/agent/sessions-greenhorn/{uuid}.json` | 全量 JSON 重写 | ✅ 已实现 |
| PI 原生格式 | `~/.pi/agent/sessions/` | jsonl 追加写入 | ❌ 尚未实现 |

**问题**：当前 `ChatPage.tsx` 的 `saveMessageToSession()` 仅调用 GreenHorn 的 PUT 接口，完全未写入 PI 原生会话文件。

### 1.2 Persona 失效根因

经过代码审查，发现 `chat-engine.ts` 中存在**重复的 persona 注入逻辑**，导致注入被覆盖失效：

```
chat.ts (line 74-77):
  if (persona) {
    systemMessage = `你是一个${persona}。\n\n`;
  }

chat-engine.ts (line 32-35):
  if (persona) {
    systemPrompt = `${persona}\n\n${systemPrompt}`;
  }
```

**冲突点**：`chat-engine.ts` 的 systemPrompt 被 `chat.ts` 传入的 systemMessage 覆盖，persona 最终未生效。

## 二、执行方案（第一批 P0 + P1）

### 2.1 P0：会话双写机制

**设计原则**：GreenHorn 读取简化文件（快），写入时双写（两边都写）

#### 双写时机

在 `sessions.ts` 的 `PUT /:id` 接口中，每次追加消息时同时写入 PI 原生 jsonl。

#### jsonl 文件规范

| 项 | 规范 |
|----|------|
| 文件路径 | `~/.pi/agent/sessions-greenhorn/{session_id}.jsonl` |
| 写入模式 | append-only（追加），不复写全文件 |
| 编码 | UTF-8 |

#### jsonl 行格式（严格遵循 PI 官方规范）

```jsonl
{"type":"session","id":"<uuid>","timestamp":"<ISO>","cwd":"<homedir>"}
{"type":"message","id":"<uuid>","parentId":"<parent>","role":"user","content":[{"type":"text","text":"<用户消息>"}]}
{"type":"message","id":"<uuid>","parentId":"<parent>","role":"assistant","content":[{"type":"text","text":"<AI消息>"}]}
```

**关键约束**：
- `content` 是数组，每条含 `type` 和 `text`
- `parentId` 指向父消息（首条消息为 null）
- session 行仅在文件开头写入一次

#### 容错策略

jsonl 写入失败不影响 GreenHorn 主流程：
```typescript
try {
  appendToPiJsonl(sessionId, event);
} catch (e) {
  console.error('PI jsonl sync failed:', e);
  // 不中断主流程
}
```

#### 涉及改动文件

| 文件 | 改动说明 |
|------|---------|
| `packages/backend/src/routes/sessions.ts` | 新增 `appendToPiJsonl()` 函数，在 `PUT /:id` 中调用 |

### 2.2 P1：Persona Bug 修复

**根因**：`chat-engine.ts` 中重复的 persona 拼接逻辑导致覆盖

**修复方案**：

| 文件 | 改动 |
|------|------|
| `packages/backend/src/services/chat-engine.ts` | 删除第 32-35 行的 persona 拼接逻辑，统一由 `chat.ts` 注入 |

**修复后的注入流程**：
```
chat.ts → 读取 persona → 拼接到 systemMessage
    ↓
chat-engine.ts → 直接使用传入的 systemMessage
    ↓
模型请求 → system: <persona> + <默认提示>
```
