## 🔴 P0（阻断性，必须先修）

### P0-1：SetupWizard 验证连接功能完全不可用

**问题**：`SetupWizardPage.tsx:148` 调用 `fetch('/api/verify', ...)`，但后端这个路由不存在。`verifyRouter` 挂载在 `/api/config`（`index.ts:28` 的 `app.use('/api/config', verifyRouter)` + `verify.ts:6` 的 `router.get('/verify')`），实际路径是 `POST /api/config/verify`。

**影响**：安装引导页第 3 步的"验证连接"按钮必报 404，用户永远无法完成模型配置。

**建议修复**：
- 方案 A：把 `SetupWizardPage.tsx:148` 的 `'/api/verify'` 改为 `'/api/config/verify'`
- 方案 B：把 `verifyRouter` 独立挂载到 `'/api/verify'`（需同步改其他调用者）

**建议方案 A，改动最小。**

### P0-2：start.bat 的 `taskkill` 会杀死所有 Node 进程

**问题**：`start.bat:90` 用 `taskkill /f /im node.exe` 无差别关闭所有 `node.exe` 进程。如果用户的 VS Code、Webpack watcher 或其他 Node 服务正在运行，关掉 GreenHorn 时会把它们一起杀了。

**影响**：用户关 GreenHorn → 其他软件也崩了。属于"不可逆破坏"级别。

**建议修复**：
```batch
:: 在启动时记录 PID
start /b "" node "%~dp0..\packages\backend\dist\index.js"
set BACKEND_PID=%ERRORLEVEL%

:: 关闭时只杀这个 PID
taskkill /f /pid %BACKEND_PID% >nul 2>&1
```
