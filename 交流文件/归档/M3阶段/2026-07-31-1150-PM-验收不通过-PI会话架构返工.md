## 二、问题清单（按严重程度排序）

### ❌ 问题 1：存储目录错误（最严重）

| 项 | 内容 |
|----|------|
| **现状** | 文件写在 `~/.pi/agent/sessions-greenhorn/{时间戳}_{uuid}.jsonl` |
| **要求** | 写在 `~/.pi/agent/sessions/--路径--/{时间戳}_{uuid}.jsonl`（PI 原生目录） |
| **修改原因** | PI 的 `/resume`、`/sessions` 等命令**只扫描 `sessions/` 目录**，永远不会读 `sessions-greenhorn/`。文件放错目录 = PI 完全看不到这些对话，用户后续的"对话整理、经验汇总"功能无数据可用。这是本次改造的根本目的，未达成。 |

### ❌ 问题 2：cwd 字段写死为 "greenhorn"

| 项 | 内容 |
|----|------|
| **现状** | `"cwd":"greenhorn"` |
| **要求** | `"cwd":"C:\\Users\\Administrator"`（真实的工作目录） |
| **修改原因** | ① PI 用 cwd 决定会话文件放在哪个 `--路径--` 子目录，必须是真实路径才能对上；② PI 读取会话时会把 cwd 作为上下文的一部分（告诉 AI "你在哪个目录工作"），写死 "greenhorn" 会让 AI 认为工作目录叫 greenhorn，完全错误。 |

### ❌ 问题 3：session 行缺少 version 字段

| 项 | 内容 |
|----|------|
| **现状** | `{"type":"session","id":"...","timestamp":"...","cwd":"..."}` |
| **要求** | `{"type":"session","version":3,"id":"...","timestamp":"...","cwd":"真实路径"}` |
| **修改原因** | PI 的会话格式有版本号（当前 v3）。缺 version 字段会导致 PI 读取时无法确认格式版本，可能按旧版解析或拒绝读取。必须补上。 |

### ❌ 问题 4：文件名时间戳格式不符

| 项 | 内容 |
|----|------|
| **现状** | `2026-07-31T03-20-35-878Z_...`（冒号换成了连字符） |
| **要求** | `2026-07-30T05-37-27-034Z_...`（保持 PI 原生格式，冒号被 ISO 规范替换为连字符——参考 PI 实际文件） |
| **修改原因** | 文件名要能排序（PI 按文件名排序显示会话）。格式必须和 PI 自己生成的文件一致，否则排序错乱。 |

### ❌ 问题 5：会话目录组织方式

| 项 | 内容 |
|----|------|
| **现状** | 所有 jsonl 平铺在 `sessions-greenhorn/` 一个目录 |
| **要求** | 按 cwd 分子目录：`sessions/--C--Users-Administrator--/`、`sessions/--d--program-GreenHorn--/` 等（`--路径--` 是 cwd 的反斜杠替换） |
| **修改原因** | PI 按工作目录组织会话。不分子目录，PI 扫描时会混乱，且换目录工作的用户会话无法区分。 |

### ⚠️ 问题 6：text 内容出现乱码 "????"

| 项 | 内容 |
|----|------|
| **现状** | 测试消息写入后变成 `"text":"????"` |
| **要求** | 中文内容完整保留，不能乱码 |
| **修改原因** | 疑似编码问题（写入时字符集处理不当）。乱码会让后续整理对话时内容不可读。 |

### ⚠️ 问题 7：验收标准第 3 条"jsonl 可被 PI 识别"未真正验证

| 项 | 内容 |
|----|------|
| **现状** | 自验证只写了"格式符合 PI 规范 ✅" |
