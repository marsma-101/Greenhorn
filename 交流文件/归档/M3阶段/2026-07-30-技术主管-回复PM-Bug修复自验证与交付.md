## 修复内容

### P0-1：SetupWizard 验证连接 404

| 文件 | 改动 |
|------|------|
| [SettingsPage.tsx](file:///d:/program/GreenHorn/packages/frontend/src/pages/SettingsPage.tsx) | 验证连接请求路径 `/api/verify` → `/api/config/verify` |
| [backend/src/index.ts](file:///d:/program/GreenHorn/packages/backend/src/index.ts) | 注册 `/api/config/verify` 路由 |

**根因**：前端 SettingsPage 写死了 `fetch('/api/verify')`，但后端路由注册在 `verifyRouter` 挂载在 `/api/config` 下，路径不匹配导致 404。

### P0-2：start.bat taskkill 无差别杀进程

| 文件 | 改动 |
|------|------|
| [start.bat](file:///d:/program/GreenHorn/scripts/start.bat) | `taskkill /f /im node.exe` → 通过 PowerShell 启动进程并记录 PID 到临时文件，停止时仅 kill 该 PID |

**根因**：原脚本用 `taskkill /f /im node.exe` 终止所有 Node.js 进程，会影响其他 Node 服务。

### P1-1：停止按钮不中止请求

| 文件 | 改动 |
|------|------|
| [ChatPage.tsx](file:///d:/program/GreenHorn/packages/frontend/src/pages/ChatPage.tsx) | 添加 `AbortController` + `useRef`，`handleStop` 调用 `controller.abort()` 中断 fetch 请求 |
| [setup.ts](file:///d:/program/GreenHorn/packages/backend/src/routes/setup.ts) | SSE 流添加 `req.on('close')` 监听，客户端断开时停止发送数据 |

**根因**：停止按钮只改了 UI 状态（`isStreaming = false`），没有实际中断网络请求，后端继续推送数据。
