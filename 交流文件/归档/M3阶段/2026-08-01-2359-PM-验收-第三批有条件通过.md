### 🔴 任务 3：A5 Hermes 验证（需修复）

**状态检测正常**：
- `/api/status` 返回 `gateway_running: true`，版本 0.17.0，pid 16968 ✅

**但对话 401**：
- 适配器调用 `POST /api/chat` 返回 **401 Unauthorized**
- 直接测 Hermes 本体 `POST 127.0.0.1:9119/api/chat` 同样 **401 Unauthorized**

**原因分析**：Hermes 的 `/api/chat` 需要**认证 token**（header 或 body），适配器没带认证信息。

**修复要求**：
1. 查 Hermes 官方 API 文档，确认 chat 接口的认证方式（token 从哪来、放哪）
2. HermesAdapter 的 chat() 加上认证
3. 实测：`/api/engines/hermes/chat` 返回真实回复

### 🔴 任务 5：B1 多引擎适配层（后端通过，前端未接入）

**后端 ✅**：
- `GET /api/engines` 返回 PI + Hermes 能力分级（chat/streaming/thinking/tools/code/filesystem）✅
- `GET /api/engines/hermes/status` 正常 ✅
- `POST /api/engines/hermes/chat` 路由存在（401 是 Hermes 认证问题）

**前端 ❌**：
- **对话页仍走旧 `/api/chat`**（chat-engine → PI），适配层接口未被前端使用
- 实测 `/chat?engine=hermes`：标识显示 Hermes，但对话回复是 **PI 的 persona「潇潇」**——证明实际还是 PI 在对话

**修复要求**：

2. engine=pi 走 PI 适配器，engine=hermes 走 Hermes 适配器
3. 实测：engine=hermes 对话时回复来自 Hermes（不是潇潇）
4. 不同引擎的 persona/config 隔离（Hermes 不该用 PI 的潇潇 persona）
