## 一、交付内容

### 1.1 P0：会话架构改造（PI 原生 jsonl）

**核心变更**：废弃 GreenHorn 独立格式，采用 PI 原生单一数据源架构

| 项 | 旧方案 | 新方案 |
|----|--------|--------|
| 会话文件 | `sessions-greenhorn/{uuid}.json` | `sessions-greenhorn/{timestamp}_{uuid}.jsonl` |
| 文件格式 | 全量 JSON 重写 | PI 原生 jsonl（append-only 追加） |
| 数据源 | GreenHorn 自有格式 | PI 原生格式（唯一数据源） |
| 标题存储 | 混在会话 JSON 中 | 独立 `titles.json` 元数据文件 |

**jsonl 格式规范**（严格遵循 PI 官方）：
```jsonl
{"type":"session","id":"<uuid>","timestamp":"<ISO>","cwd":"greenhorn"}
{"type":"message","id":"<uuid>","parentId":"<父id>","role":"user","content":[{"type":"text","text":"<文本>"}]}
{"type":"message","id":"<uuid>","parentId":"<父id>","role":"assistant","content":[{"type":"text","text":"<文本>"}]}
```

**涉及改动**：
| 文件 | 改动说明 |
|------|---------|
| `packages/backend/src/routes/sessions.ts` | 完全重写（474 行 → 474 行），新增 jsonl 读写、标题元数据、自动迁移 |

### 1.2 P1：Persona Bug 修复

**根因**：`chat-engine.ts` 中存在重复的 persona 注入逻辑，导致被覆盖失效

**修复**：删除 `chat-engine.ts` 第 32-35 行的重复逻辑，统一由 `chat.ts` 注入

| 文件 | 改动 |
|------|------|
| `packages/backend/src/services/chat-engine.ts` | 删除 4 行重复代码，persona 注入入口统一 |

## 二、实现细节

### 2.1 新增功能

| 功能 | 说明 |
|------|------|
| jsonl 追加写入 | 每条消息 append-only 追加，不复写全文件 |
| 标题元数据管理 | `titles.json` 独立存储自定义标题，读取时优先使用 |
| 自动标题生成 | 第一条用户消息前 30 字自动作为默认标题 |
| 旧会话迁移 | 启动时自动将 `sessions-greenhorn/*.json` 迁移为 jsonl |
| 删除同步 | 删除会话时同步删除 jsonl + 元数据条目 |

### 2.2 容错机制

| 场景 | 处理方式 |
|------|---------|
| 迁移失败 | `console.error` 记录，不阻塞启动 |
| jsonl 写入异常 | try-catch 包裹，返回友好错误给前端 |
| 标题元数据损坏 | 返回空对象 `{}`，降级为自动标题 |
