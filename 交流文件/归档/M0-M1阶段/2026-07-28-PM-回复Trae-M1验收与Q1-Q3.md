## 二、回答 Q1-Q3

### Q1：PI 检测逻辑

你的实现方案没问题。默认路径对照：

| 平台 | 默认路径 |
|------|---------|
| **Windows** | `C:\Users\<用户名>\.pi\agent\` |
| **macOS / Linux** | `~/.pi/agent/` |

不过按最新需求（数据目录自选），检测逻辑需要调整为：

```
① 先检查环境变量 PI_CODING_AGENT_DIR
   → 如果有，检测该路径下是否存在配置文件
② 如果没有环境变量
   → 检测默认路径 ~/.pi/agent/
③ 如果都没有
   → 返回 { installed: false }
```

## 三、新增需求同步（数据目录自选）

刚加的一个新需求，独立出来说明：

### 需求描述

不让用户的数据默认存到 C 盘。用户应该能选择：

1. **PI 源码保存位置** — 克隆 PI 到哪（例如 `D:\GreenHorn\pi-source\`）
2. **PI 配置数据保存位置** — `auth.json`、会话等存哪（例如 `D:\GreenHorn\pi-config\`）

### 实现方式

**配置数据**：PI 原生支持 `PI_CODING_AGENT_DIR` 环境变量覆盖配置路径。GreenHorn 启动时设置即可，不碰 PI 源码。

**源码路径**：GreenHorn 在选择目录时确定克隆位置，记录到自己的配置文件中。

### 前端新增页面

"选择文件保存位置"页面，放在安装流程的第一步：

```
步骤 1/4：选择保存位置
步骤 2/4：安装 PI
步骤 3/4：配置 API Key
步骤 4/4：开始对话
```

### 影响范围

| 模块 | 影响 |
|------|------|
| A1 前端 | 新增"选择目录"页面 |
| A2 后端 | 启动时注入 `PI_CODING_AGENT_DIR`；旧目录检测提示 |
| A6 文档 | 在部署指南和 FAQ 中说明 |
| A7 DevOps | 安装脚本中预留数据目录参数 |

### 优先级

M1 先做核心对话流程。这个需求**放到 M2**，和安装流程一起做。
