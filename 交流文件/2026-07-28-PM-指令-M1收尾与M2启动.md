## 一、M1 收尾工作（本次完成）

### 核心变更：先用 Ollama 验证对话链路

**不急着申请 DeepSeek Key、不急着集成 PI SDK。** 先把本地 Ollama 打通，验证"前端发消息 → 后端调模型 → 流式回复到前端"这一整条链路。

### 具体任务

#### 任务 1：Ollama 检测 + 对话

1. `GET /api/ollama/check` — 检测本机 Ollama 是否安装并运行
   - 请求 `http://localhost:11434/api/tags`
   - 返回：`{ installed: true, models: ['qwen3.5:9b', ...] }`
2. 对话引擎（`chat-engine.ts`）优先尝试本地 Ollama
   - 配置为 ollama provider 时 → 调 `http://localhost:11434/v1/chat/completions`
3. 前端首页的 PI 检测卡片 → 同时显示 PI 和 Ollama 状态

#### 任务 2：Ollama 加入供应商预设

在 `model-providers.ts` 中已经有的 Ollama 配置基础上，补充更友好的界面呈现：

```json
{
  "id": "ollama",
  "name": "Ollama（本机运行）",
  "description": "本地运行开源模型，完全免费，无需 API Key",
  "url": "http://localhost:11434",
  "models": ["qwen3.5:9b", "llama3.1:8b", ...],
  "recommendLevel": "recommended"
}
```

#### 任务 3：验证链路

```
浏览器 → 选择 Ollama → 发消息
                    ↓
          后端 POST /api/chat (provider=ollama)
                    ↓
          调 http://localhost:11434/v1/chat/completions
                    ↓
          SSE 流式回复 → 浏览器显示
```

## 二、架构预留：高级设置入口

**当前设置面板保持简洁**（模型 + Key + 主题 + 帮助开关），**但预留一个"高级设置"按钮**。

### 设计

```
┌─ ⚙️ 模型 ───────────────┐
│  模型提供商：[ Ollama ▼ ]│
│  API Key：   [********]  │
│  API 地址：  自动填好    │
│  [ 验证连接 ] ✅         │
├──────────────────────────┤
│  🎨 外观                 │
│  💡 帮助开关              │
├──────────────────────────┤
│  [ 🔧 高级设置 ]  ← 新加  │
└──────────────────────────┘
```

### 点击"高级设置"后的交互

点击后 → 弹出侧边抽屉或新页面 → 显示 PI 配置文件的内容列表：

```
🔧 高级设置
（以下内容是 PI 配置文件中的设置，修改后直接写入 ~/.pi/agent/settings.json）

┌─ 对话 ─────────────────┐
│  思考显示：[ 展开 ▼ ]   │
│  思考级别：[ medium ▼ ] │
│  温度：              │
│  上下文长度：              │
└────────────────────────┘

┌─ 工具 ─────────────────┐
│  自动执行：[ 从不 ▼ ]   │
│  项目信任：[ 每次都问 ▼ ]│
└────────────────────────┘
```

**实现方式**：
- 前端直接调用后端 API 读写 `~/.pi/agent/settings.json`
- 后端封装一个通用的配置读写接口：`GET/PUT /api/pi/settings`
- 高级设置的 UI 内容——留到 M3/M4 再做，M2 只加按钮入口

### 优先级

| 阶段 | 做什么 |
|------|--------|
| **M2** | 加"高级设置"按钮（入口），页面内容留空或写"即将上线" |
| **M3+** | 逐步把 PI 配置文件中的常用设置映射到高级设置页面 |
