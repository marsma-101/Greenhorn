## 二、修复详情

### ✅ 修复 1：pnpm build scripts 配置

**根因**：`pnpm-workspace.yaml` 中：
```yaml
allowBuilds:
  better-sqlite3: set this to true or false  # ← 占位符，pnpm 10 不认
  esbuild: set this to true or false           # ← 同上
```

pnpm 10+ 忽略未知值的 build scripts，导致 esbuild 的 postinstall 不执行。

**修复**：改用 pnpm 10 标准的 `onlyBuiltDependencies`：
```yaml
packages:
  - 'packages/*'

onlyBuiltDependencies:
  - esbuild
  - better-sqlite3
```

**验证**：`pnpm install --frozen-lockfile` 正常通过（esbuild 二进制正常生成）。

**涉及文件**：[pnpm-workspace.yaml](file:///d:/program/GreenHorn/pnpm-workspace.yaml)

---

### ✅ 修复 2：start.bat errorlevel 判断失效

**根因**：Windows batch 经典坑——**括号块内 `%errorlevel%` 在块解析时就被预展开为旧值**。

例如：
```batch
if %errorlevel% neq 0 (   ← 此处 %errorlevel% 已被展开为 0
    echo [错误] ...
    exit /b 1
)
```

即使 `call pnpm build` 失败，`%errorlevel%` 在块解析时已固定为 0，检测永远不成立。

**修复**：
1. 添加 `setlocal enabledelayedexpansion`
2. 所有错误检测改用 `if errorlevel 1`（运行时动态判断，不受预展开影响）
3. 变量引用在需要时使用 `!VAR!` 延迟展开语法

**关键改动**：
```batch
# 之前（错误）
if %errorlevel% neq 0 (

# 之后（正确）
if errorlevel 1 (
```

**涉及文件**：[start.bat](file:///d:/program/GreenHorn/scripts/start.bat)
