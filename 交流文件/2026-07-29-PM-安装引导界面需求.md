## 一、需求背景

用户选择引擎（如 PI）后，GreenHorn 需要完成一系列"初始化"操作——拉取代码、安装依赖、检查环境、配置模型等。这些操作**必须全部 GUI 化**，用户不该接触命令行。

目前的启动器（`scripts/launcher.js`）只是一个临时方案。真正的产品里，**GreenHorn 自身应该能完成安装引导**，不需要外部脚本。

## 三、需要实现的具体功能

### 3.1 环境检测（后端实现）

用户点击"开始设置"后，后端自动检测本机环境：

```typescript
// GET /api/setup/check-env
// 一次性返回所有环境信息
interface EnvCheckResult {
  // 运行环境
  nodeInstalled: boolean;
  nodeVersion?: string;
  gitInstalled: boolean;
  pnpmInstalled: boolean;
  
  // 引擎相关
  piInstalled: boolean;      // 是否已有 PI
  piPath?: string;
  
  // Ollama
  ollamaInstalled: boolean;
  ollamaRunning: boolean;
  ollamaModels: string[];
  
  // 系统信息
  platform: string;          // 'win32' | 'darwin' | 'linux'
  userHome: string;          // C:\Users\xxx
  diskSpace: string;         // C 盘剩余空间（友好显示）
}
```

### 3.2 镜像拉取（后端实现）

```typescript
// POST /api/setup/install
// 开始安装流程
interface InstallRequest {
  engine: 'pi';              // 选择的引擎
  sourcePath: string;        // 源码存放路径
  configPath: string;        // 配置存放路径
  skipSource?: boolean;      // 已有源码时跳过
}

// 返回：SSE 流式进度事件
// 类似 /api/chat 的 SSE 方式
interface InstallEvent {
  type: 'progress';          // 进度更新
  phase: 'env_check' | 'git_clone' | 'npm_install' | 'config_init';
  progress: number;          // 0-100
  message: string;           // "正在拉取 PI 源码..."
}

interface InstallEventError {
  type: 'error';
  message: string;           // "拉取失败：网络连接超时"
  suggestion?: string;       // "可以试试切换镜像源"
}

interface InstallEventDone {
  type: 'done';
  success: boolean;
}
```

### 3.3 安装进度页面（前端实现）

**UX 要求**（同之前的设计稿）：

| 元素 | 要求 |
|------|------|
| 总进度条 | 大进度条，百分比 + 动画 |
| 分阶段明细 | 环境检测 / 拉取源码 / 安装依赖 / 配置初始化，每行独立状态 |
| 当前操作文案 | "正在下载 pi 的依赖包..."（大白话） |
| 暂停/取消 | 底部操作按钮 |
| 完成自动跳转 | 安装完毕 → 自动进入下一步 |
| 失败提示 | 醒目红色框 + "这是因为..." + "你可以试试..." |

### 3.4 引擎安装后的配置初始化

安装完成后，需要自动做几件事：

| 操作 | 说明 |
|------|------|
| 设置 `PI_CODING_AGENT_DIR` 环境变量 | 写入启动脚本或系统环境变量，指向用户选的配置路径 |
| 创建初始配置文件 | 如果 `auth.json` / `models.json` 不存在，创建空模板 |
| 记录安装信息 | 保存安装路径到 GreenHorn 自己的配置中，下次启动免安装 |

## 四、启动器脚本的后续定位

当前 `scripts/launcher.js` 是临时方案，最终要**被 GreenHorn 自身的安装引导流程替代**——用户打开 GreenHorn 就能走完安装，不需要先运行一个外部脚本。

但 `launcher.js` 可以保留作为"桌面入口"：
```
launcher.js 的角色最终版：
  · 提供一个桌面快捷入口
  · 启动 GreenHorn 服务（如果没运行）
  · 打开浏览器
  · 具体的安装/配置 → 交给 GreenHorn 自身
```
