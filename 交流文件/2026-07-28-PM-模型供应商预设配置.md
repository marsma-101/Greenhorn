# 模型供应商预设配置

> 用途：后端（A2）直接集成到代码中，前端（A1）渲染为选择列表
> 设计目标：用户点选供应商和模型 → 系统自动填入 URL → 提供注册直达链接
> 状态：📝 定稿，可直接编码

---

## 一、数据结构（TypeScript 接口）

```typescript
// 模型提供商
interface ModelProvider {
  id: string;                // 唯一标识
  name: string;              // 显示名称
  description: string;       // 一句话说明
  url: string;               // API 基础地址
  registerUrl: string;       // 注册/申请 API Key 的页面
  models: Model[];           // 支持的模型列表
  isBuiltin: boolean;        // 是否内置（PI 原生支持）
  region: 'china' | 'global'; // 网络区域
  recommendLevel: 'recommended' | 'alternative' | 'advanced';
}

// 模型
interface Model {
  id: string;                // 模型 ID（传给 API）
  name: string;              // 显示名称
  description: string;       // 一句话说明
  features: string[];        // 特性标签：如 "中文强" "代码强" "便宜"
}
```

## 三、前端交互流程

用户看到的步骤：

```
① 选供应商               ② 选模型                ③ 配置完成
┌──────────────┐       ┌──────────────┐       ┌──────────────┐
│ ⭐ DeepSeek  │       │ ○ V3         │       │ DeepSeek     │
│ 通义千问      │  →   │ ● R1 ⭐推荐   │  →   │ · V3         │
│ 智谱          │       │              │       │ · API Key    │
│ Ollama        │       │              │       │ · URL ✓ 已填 │
│ ...          │       │              │       │ [注册链接]   │
└──────────────┘       └──────────────┘       └──────────────┘
                                                      │
                                                      ▼
                                               [ 验证连接 ] → ✅
```

### 关键交互细节

| 场景 | 交互 |
|------|------|
| **选供应商** | 卡片列表，每张显示名称 + 一句话描述 + 推荐标签 |
| **选模型** | 选中供应商后展开模型列表，每个模型显示名称 + 特性标签 |
| **URL 自动填入** | 选中模型后 URL 自动填入输入框（不可编辑但可见） |
| **注册直达** | 显示"还没有 Key？[ 去 DeepSeek 官网获取 ]" 按钮，点击打开新标签页 |
| **Key 输入** | 输入框占位提示："粘贴你的 API Key 到这里" |
| **验证连接** | 点验证后显示成功✅ 或 失败❌ + 原因 |
| **保存** | 验证通过后自动保存，用户回到对话界面 |

## 四、后端实现建议

### 数据来源

本配置文件可以有以下两种实现方式：

**方案 A（推荐）：硬编码为常亮数据**

```typescript
// src/backend/config/model-providers.ts
export const MODEL_PROVIDERS: ModelProvider[] = [ /* 上面的完整列表 */ ];
```

优点：零配置、开箱即用、更新随版本走
缺点：新增供应商需更新版本

**方案 B：配置文件化**

```json
// ~/.pi/agent/model-providers.json
```

优点：用户可自定义
缺点：需要维护文件读取逻辑、默认配置回退

**PM 建议**：MVP 用方案 A，后续版本支持方案 B 覆盖。

### API 接口

```typescript
// GET /api/model-providers
// 返回预设供应商列表（前端用来渲染选择界面）
Response: ModelProvider[]

// GET /api/model-providers/:id
// 返回单个供应商详情（含模型列表）
Response: ModelProvider

// POST /api/model-providers/verify
// 验证 API Key 是否有效
Body: { providerId: string, apiKey: string, modelId?: string }
Response: { success: boolean, message: string, latency?: number }
```

## 六、风险提示

1. **API 地址可能变更** — 各厂商偶尔会调整接口地址，建议加一个"检查更新"的机制或社区维护的更新源
2. **模型 ID 可能变更** — 厂商会改名或废弃旧模型，建议前端显示名称和 ID 分离，变更时只需改后端数据
3. **OpenAI 国内访问** — 明确提示需要特殊网络环境，避免用户购买后才发现用不了
