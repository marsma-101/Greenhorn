## 二、需要沟通的问题

### Q1：关于"验证连接"按钮（UX 文档 3.3 节）

UX 文档要求 API Key 输入后有"验证连接"按钮。这个功能需要后端提供一个专有 API 端点。

**技术方案建议**：
```typescript
POST /api/config/verify
Body: { provider: 'deepseek', apiKey: 'sk-xxx', baseUrl: '...' }
Response: { success: true } | { success: false, message: 'Key 好像不对哦...' }
```

**确认**：是否按此方案实现？验证时是否需要实际发送一条消息测试，还是只检查 API 端点可达性？

### Q2：关于"一键安装"流程（UX 文档 3.2 节）

安装进度页设计得很好，但需要确认：

1. **MVP 是否真的需要"一键安装"？** 用户本机已经有了 PI 工程（`D:\program\pi-agent`），MVP 阶段可以先直接使用现有的 PI，跳过安装流程
2. 如果先跳过安装，首页只需要显示"PI · 编码智能体"卡片，状态为"已就绪"
3. **建议**：安装模块（F1）作为 P1 功能，在 M2 阶段实现，M1 先专注于对话和配置

**请PM确认**：MVP 是否可以先跳过"一键安装"流程，直接使用本机已有的 PI？

### Q3：关于"会话浏览"（UX 文档 3.5 节）

UX 文档中设置面板包含了"查看更新日志"，但未提及"会话浏览"页。PRD 的 F8 功能提到了会话浏览。

**建议**：MVP 可以暂时隐藏会话浏览页入口，但对话工作台的数据层（SQLite 会话存储）还是要实现，为后续功能打基础。

**确认**：会话浏览页是否按 PRD 的 P2 优先级，放在 MVP 之后再做？

### Q4：关于"设置面板"的复用策略

UX 文档的设置面板设计很清晰。但 pi-web-switch 已有配置面板，重点确认：

- **复用策略**：直接 fork pi-web-switch 的配置面板代码，按 UX 设计改造 UI
- **不保留** pi-web-switch 的仪表盘（DashboardPage）和用量统计功能
- **保留**：模型选择、Provider 管理、API Key 管理、主题切换

**确认**：是否同意这个复用策略？

### Q5：关于"流式打字速度"

UX 文档要求"逐字稳定输出，速度不过快"。但 SSE 流式传输的速度取决于 LLM 的响应速度和技术主管无法控制 LLM 的生成速度。

**技术方案**：
- 后端不做额外限速（延迟用户体验不好）
- 前端可以加一个"打字机效果"动画，用 CSS 控制文字逐渐显示的速度
- 提供一个"加速"选项（在设置中），让用户选择是否要平滑动画

**确认**：是否接受前端做打字机动画，而不是后端限速？
