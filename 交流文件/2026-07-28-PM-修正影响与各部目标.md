### A2 — 后端开发智能体

**核心目标**：一个很薄的 Node.js 脚本

```
GreenHorn 后端代码估算 ~200 行
├── Web Server（serve 前端 + API 路由）        ~50 行
├── PI SDK 对话桥（接收请求 → 调 SDK → SSE）   ~80 行
├── 配置文件读写（auth.json / models.json）     ~40 行
└── 安装流程（git clone + npm install）         ~30 行
```

| 模块 | 改前 | 改后 |
|------|------|------|
| Web Server | Express，serve 前端 | ✅ **不变** |
| 对话桥 | 调 PI SDK | ✅ **不变** |
| 配置文件读写 | 读写 `~/.pi/agent/` | ✅ **不变** |
| 安装流程 | git clone PI | 🔄 **简化** — 只拉 PI，不拉 pi-web-switch |
| 会话管理 | SQLite 存会话 | 🔄 **删除** — PI 用 JSONL 自己管理 |
| 数据统计 API | 有 | 🔄 **删除** — 不做 |
| API 数量 | ～10 个端点 | 缩减为 **3 个核心端点** |

**最终 API 端点**：
| 端点 | 用途 |
|------|------|
| `POST /api/chat` | 发消息，返回 SSE 流式事件 |
| `GET /api/config` | 读 PI 当前配置（模型、Key 等） |
| `PUT /api/config` | 写 PI 配置（更新 Key、换模型） |
| `POST /api/install` | 触发安装流程 |

### A3 — PI 引擎对接智能体

**核心目标**：M0 已完成 ✅

M0 验证了 PI SDK 嵌入方案可行，输出了一份详实的验证报告。后续只需：
- 维护 `pi-adapter` 模块（目前就是调 PI SDK，非常薄）
- 为未来其他引擎预留 Adapter 接口定义（已设计好 `EngineAdapter` 接口）

**本次修正影响**：无。架构简化后反而更符合 M0 的验证结论——"通过 PI SDK 嵌入，直接调它就行，不用包一层厚后端"。

### A5 — 测试智能体

**核心目标**：覆盖主路径 + 异常场景

**测试范围**（本次修正影响：✅ 范围缩小，更聚焦）：

```
主路径测试（P0）：
  打开 → 看到首页 →
  选择 PI →
  安装（模拟网络好/差） →
  填 Key（有效/无效） →
  发消息 → 看到回复 →
  换模型 → 继续对话

异常场景测试：
  · 网络断开时安装 → 错误提示 + 重试
  · API Key 错误 → 验证失败提示
  · PI 进程异常 → 错误兜底
  · 浏览器关闭后重开 → 配置保留
```

**不需要测的**：
- ❌ 会话历史浏览
- ❌ 数据统计
- ❌ 温度/上下文参数调节
